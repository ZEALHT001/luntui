# 山海毕设报告 × aboard：对比与可采纳改进

> 依据：`开源参考/山海/定稿-毕业设计说明书.pdf`（57 页；**实际只导出了摘要、目录、第三章、第四章和致谢**，
> 第 1、2、5、6、7 章只有目录条目，所以涉及第 5、6 章的部分只能按摘要和目录讨论）与
> 同目录 `代码.zip` 中最终版底盘固件（`Chassis/`，Keil 工程）。
> 对照对象：本仓库 `aboard/`（A 板 STM32F427，VMC + 六状态 LQR + LESO，333 Hz）。
> 文中引用的行号以本文写作时的 `aboard` 工作区为准。

---

## 0. 一句话结论

报告是**并联偏置五连杆 + 双腿各自 LQR + 增量 MPC 补偿**的巡检平台方案；
aboard 是**串联四杆 + VMC + 六状态 LQR + LESO** 的比赛平台方案，观测器、
故障门控、遥测和工具链整体比报告成熟一个量级。

但报告在**"力/加速度观测 → 事件触发"**这条链路上比我们细：它把关节力矩反解成
支撑力 FN、碰撞力 Ft，再用这两个物理量去触发离地、上台阶和跳跃，而不是靠
LQR 输出或轮速阈值。这一点正是我们可以低成本吸收的部分。

**最值得注意的是：报告正文写得最重的三项（K(L0) 三次拟合、质心偏移 θ_target
补偿、LQR 串增量 MPC），在随附源码里全部被宏关掉。** 最终真机跑的是固定 K 阵
+ FN 门控。这说明这三项在实机上要么收益不足、要么不稳，我们不应该照着正文抄，
而应该只借它的**结构**和**离线标定流程**。

## 3. 建议采纳的改进

排序依据：收益 ÷ （改动量 × 风险）。P0 当天可做，P1 需要一到两次实机，P2 是方法建设。

### P0-1 用龙伯格观测器替代二阶微分项的"差分 + 低通"

**为什么**：aboard 的 `dd_length` / `dd_theta` 是纯差分再一阶低通（α = 0.20，
`vmc_probe.c:6144–6210`）。这两个量直接进 FN 支撑力公式（`vmc_probe.c:4224`），
而我们下一步要加的碰撞力 Ft 对它的敏感度更高（Ft 里带 m_w·ddy_w + I_w/R²·ddy_w）。
报告的图 4.2 是同一台机器上"差分+低通"和"龙伯格"的对比：尖峰噪声明显更低，
且更贴真实值。

**报告/山海的做法**（`Chassis/Model/Observer.c`，真的只有 4 行）：

```c
/* 标准形式（源码把 /dt 折进了系数）；状态 (v̂, â)，量测 y = dL0_meas，dt = 2 ms */
v_hat += dt * a_hat;
e      = y - v_hat;
v_hat += l1 * e;          /* l1 = 0.12  */
a_hat += l2 * e;          /* l2 = 0.60  */
```

要点：**先按模型预测（`v += dt·a`），再用速率残差同时修 v 和 a**。因为多了一个
积分路径，同样的噪声抑制下相位滞后比"差分 + 一阶低通"小得多。

**落点**：把 `vmc_probe.c:6144` 起的两个分支换成上面四行，`VMC_LEG_ACCEL_FILTER_ALPHA_DEFAULT`
退役（保留宏做兼容）。增益要按 333 Hz 重算：山海的 l1 = 0.12 @500 Hz 等价连续
L1 ≈ 60 rad/s，l2 = 0.6 @500 Hz 等价 L2 ≈ 300 s⁻²，对应 ωn ≈ 17 rad/s、ζ ≈ 1.7（过阻尼）。
搬到 333 Hz：`l1 = 60/333 ≈ 0.18`，`l2 = 300/333 ≈ 0.90`。

**怎么验**：不用上机。写一个回放脚本，读现有 RTT 日志里的 `d_length` / `d_theta` / FN，
离线同时算两种微分，比较三件事：稳态 FN 方差、落地瞬间 FN 最小值（误判离地）、
FN 穿阈值的次数。aboard 的离地判据是 35 N / 20 ms 确认，只要新观测器不增加
误触发、且落地那一拍的 FN 更低（更容易判到触地），就换。

**风险**：过阻尼观测器在大冲击下会"记住"错误的加速度，需要给 a_hat 加硬限幅
（例如 ±20 m/s²），并在 `acceleration_valid == 0`（无使能/超时）时清零——这段逻辑已存在，
只要把限幅加上。

### P0-2 翻滚补偿补一条差动力通道

**为什么**：我们现在只有腿长通道（`roll_comp`），它受机械行程硬限（`vmc_probe.h:335`
那张表：SHORT 只能伸 205 mm 不能缩，LONG 只能缩 25 mm），而且在 14.7° roll 就饱和。
单边桥、侧向被撞、高速过弯这些工况需要的是**快**的力矩，腿长环是位置环，天生慢。

**山海的实现**（`Chassis/Model/Locomotion_Controller.c`，且是**实际启用**的）：

```c
/* 腿长通道：由实测两腿长差 + roll 几何解，不是简单增益 */
Delta_L0 = L0_r - L0_l;
A = Delta_L0*cos(roll - roll_target) + 2*Rl*sin(roll - roll_target);
B = -Delta_L0*sin(roll - roll_target) + 2*Rl*cos(roll - roll_target);
tan_delta = A/B;  dL0_r = Rl*tan_delta;  dL0_l = -Rl*tan_delta;

/* 力通道：roll 的 PD，左右反对称叠加到 F */
PID(roll 与 dRoll, kp 500 / kd 25, 输出 ±50 N)  ->  F_l = +out,  F_r = -out
```

力通道是差动的（左右一正一负），**不改变总支撑力**，所以不影响腿长和竖直方向
平衡，这一点和我们的 leg sync 在 Tp 域加差动项是同一个思路。

**落点**：`vmc_probe.c` 腿长目标合成处（`:6709` 一带）之后、`vmc_leg_force` 之前，
给 `force` 加一项 `roll_force`；参数进 `vmc_control` 并在 `vmc_lqr_rtt.c` 里开放，
沿用现有的 roll 使能/门控（两腿 FN 都在阈值以上才允许作用）。

**怎么验**：`tools/roll_comp_report.py` 已经能报告 roll 通道的效果；加一条"差动力"指标，
在单边桥/斜坡上各跑一次，比较 roll 峰值和恢复时间，以及左右支撑力的差。

**风险**：差动力会通过 VMC 变成两个关节的力矩差，和 leg sync（Tp 域）耦合。
先给 ±50 N 上限、并且只在 `roll_comp_enable` 且两腿着地时生效；如果出现
左右腿"互顶"，说明两条差动通道抢同一自由度，就把 leg sync 的 kp 降一档再试。

### P0-3 偏航改成"外环角 → 内环角速度"双环，并对内环限幅

**为什么**：现在 `vmc_update_yaw_hold_current()` 是单环 PD 直接出电流（kp 10000 / kd 1000 计数单位）。
问题有两个：
1. D 项吃的是陀螺原始角速度，spin 模式 9 rad/s 时噪声被放大成电流抖动；
2. 没有角速度上限，高转速下打滑或侧倾时无法在"速度层"收住。

**山海的实现**（`Locomotion_Controller.c`，实际启用，`w_limit = 2.5 rad/s`）：

```c
w_cmd = clip(K1 * (yaw - yaw_target), -w_limit, +w_limit);   /* K1 = 14.14 */
tau   = K2 * (dYaw + w_cmd);                                  /* K2 = 5.48  */
T_left = -tau/2;  T_right = +tau/2;
```

结构上就是：角度误差 → **限幅后的角速度指令** → 角速度跟踪 → 差动力矩。
报告 3.6.3 特别说明了为什么要双环：**限幅必须放在内环指令上**，才能配合
3.6.3.2 的防外翻。

**落点**：`vmc_probe.c:5760`。保留现有 deadband、使能门控、`yaw_hold_current_limit`，
把 PD 换成"外环 P + 限幅 + 内环 P"。新增 `yaw_hold_rate_max`（rad/s）与
`yaw_hold_kp_outer`；我们有 spin 模式，`yaw_spin_rate` 应作为速率前馈直接加到
内环指令上，而不是让外环去追。

**怎么验**：`tools/test_spin_line.py` / `test_spin_speed.py` 已经覆盖 spin；
补一个阶跃转向（鼠标/摇杆给大角速度指令）看超调和电流峰值。

**风险**：外环增益过大在 spin 时会自激。先用"外环限速 = 当前 spin 速率 × 1.2"，
再逐步放开。

### P0-4 高速转向的离心力补偿 ΔF

**为什么**：受击、急转、spin 时离心力会把机体向外侧翻，现在完全靠 LQR 的
φ/x 项兜，属于"事后恢复"；报告是**前馈**抵消。

**山海的实现**（`Locomotion_Controller_HighSpeed_Control`，实际启用）：

```c
hg    = (L0_l + L0_r) / 2;
DeltaF = (M + 2*m_p + 2*m_w) * dx * dYaw * hg / Rl;
F_l -= 1.5 * 0.5 * DeltaF;
F_r += 1.5 * 0.5 * DeltaF;
```

即"整机质量 × 向心加速度 × 质心高度 ÷ 半轮距"= 需要的外侧支撑力增量，左右
一减一加（总支撑力不变），再乘 1.5 的余量。注意山海这里 `hg` 用的是**平均腿长**
（他们机体贴得低，腿长近似等于质心高度）；我们机体更高，应该用**实测质心高度**
（含机体的那一段），否则前馈会系统性偏小。

**必须同时做的第二件事**：这个前馈能力是有限的。按 M ≈ 20 kg、hg ≈ 0.3 m、Rl = 0.23 m，
取 v = 3 m/s、ω = 9 rad/s 得 ΔF ≈ 700 N 的总量（每腿再取 0.75 倍 ≈ 530 N），已经
顶到 500 N 的力上限 —— 所以真正起保护作用的不是前馈，而是**限制 v·ω 的乘积**。
由力矩平衡可推得临界条件：

```
v * ω <= g * Rl / hg
```

举例 Rl = 0.23 m、hg = 0.30 m：约 **7.5 m/s·rad/s**，即 3 m/s 时 ω 最多 2.5 rad/s
（正好是山海的 `w_limit` 默认值）；spin 时 v 很小，ω 才可以大。建议把这个约束
写成 `yaw_rate_limit = g*Rl/(hg*|dx|)`，与 `yaw_spin_rate_max` 取较小值。
两个数都要实测，所以它和轮距一样，属于"先测后调"的前置工作。

**前置条件**：`Rl`（半轮距）我们**没有实测**，这也是打滑判据 A 一直被禁用的原因
（`vmc_probe.h:634`）。测轮距是一分钟的事，却没做 —— 两个功能都卡在这一个数上，
建议先做。

**怎么验**：低速起步（0.5 m/s + 1 rad/s）确认 DIRECTION 符号、ΔF 量级正确；再逐步
提高 v·ω 到 5 左右，看 roll 是否比不补偿时小。

**风险**：ΔF 是差动力，和 P0-2 的 roll 力通道在同一自由度上。**两项必须一起设计**：
建议合成一个 `differential_force` 量（roll PD + 离心前馈），各自限幅后相加，
而不是在两个地方各加一次。

### P1-1 用碰撞力 Ft 做上台阶触发（与现有判据并行）

**为什么**：现在的触发是"LQR 轮力矩尖峰 > 1.45 N·m + 两腿角 > 0.19 rad + 掉速"
（`vmc_probe.c:1973` 起）。力矩阈值是**控制器输出**，K、锚点、腿长一变，同一个台阶
就可能不触发；掉速判据又和打滑判据共用轮速，容易混。碰撞力是**物理量**，不随增益漂移。

**山海的实现**（`Observer_GetFt`）：

```c
N     = F*sin(theta) + Tp*cos(theta)/L0;      /* 代码注释：正确式应为 F*sin - Tp*cos/L0 */
I_w   = 4.077e-4;
ddy_w = a_yE - ddL0*sin(theta) - 2*dL0*dtheta*cos(theta)
              + L0*ddtheta*cos(theta) + L0*dtheta^2*sin(theta);
Nf    = T_wheel/R - I_w*ddy_w/(R*R);
Ft    = Nf - N - m_w*ddy_w + 10.0f;           /* +10 是经验偏置 */
```

触发条件（`Chassis.c:568` 起，实际启用）：两腿 FN 都正常、腿长已到 0.40 m 保持
约 400 ms、`|Ft_l + Ft_r| > 60 N`；配合 STP 激光 < 800 mm 和速度 > 0.3 m/s 做前置门控。

**落点**：紧挨 `vmc_side_support_force()`（`vmc_probe.c:4224`）加一个
`vmc_side_collision_force()`，复用它的 F/Tp 反解和 theta 符号约定；触发逻辑给
`vmc_stair_update()` 增加一个"力判据"分支，与现有力矩判据做 OR（先并行观察，
日志里同时记录两个判据的触发时刻，比较谁先谁稳）。

**怎么验**：`tools/slip_capture.py` 那套高速二进制流已经带有关节力矩和轮力矩，
可以回放算 Ft；先拿历史上一堆上下台阶的日志跑，看 60 N 阈值能不能分开"上台阶"
和"平地急停/撞墙"。

**注意（两条，都会直接影响阈值）**：

1. 这段公式里 `ddL0`、`ddtheta` 就是 P0-1 要换的量，**先做 P0-1 再算 Ft**，
   否则噪声会把阈值淹掉。另外 `m_w` 我们取 0.4 kg，山海取 `0.2265×20 ≈ 4.53 kg`
   （等效轮+腿质量），所以同样的加速度噪声在他们那里对 Ft 的影响比我们大一个量级
   —— 我们要按 0.4 kg 重算阈值，**60 N 不能直接抄**。
2. 顺手修一个已记录的旧账：`docs/MPC分支工作总览_2026-11-06至11-12.md:175` 记着
   `motion.wheel_dx` 没除 2（差 2 倍），它只被上台阶检测当速度阈值用，所以现在
   `VMC_STAIR_SPEED_THRESHOLD_DEFAULT = 0.35` 实际门槛只有 0.175 m/s。改触发判据时
   一起修掉，否则新老判据不能公平对比。

### P1-2 跳跃高度标定：用能量模型 + 实测表，而不是只靠试参

**为什么**：`VMC_JUMP_LENGTH_KP/KD/SUPPORT_FORCE` 现在都是"试出来再记在注释里"
（`vmc_probe.h:150–205` 那段注释本身就是一部调参史：0.91 → 1.37 m/s）。
报告 3.6.7 给了闭式关系：起跳段能量守恒 → 离地速度 v、起跳时间 t2 → 斜抛高度
H 与时间 t3 → 收腿推力 F' → 落地时间 t4。这套式子不需要精确模型，只要质量、
行程和气弹簧力（我们没有气弹簧，所以 F 就是纯电机推力，比他们更干净）。

**更有价值的其实是那张经验表**（山海源码 `Chassis_ModelJump` 的注释）：

```
F0 = 120.0 N -> 0.20 m      189.9 N -> 0.30 m      261.9 N -> 0.38 m
     163.7 N -> 0.25 m      229.2 N -> 0.35 m      301.4 N -> 0.40 m
```

他们用同一台机器把"推力 → 高度"标成了一条线。我们有 `tools/jump_report.py`
已经在测起跳速度和高度（±2 采样窗），完全可以做同样的事：跑一组力，拟合
`H = f(F0)`，然后**由目标高度反解力**，而不是固定参数。这比抄他们的数有用得多，
因为构型不同、没有气弹簧，数值一定不一样。

**落点**：新增 `jump_height_target`（可选）与 `jump_force_from_height()` 查表/拟合；
`vmc_jump_enter_stage(EXTEND)` 时按目标高度设力。落地时序方面：`LAND` 现在靠
"关节力矩 > 3.0 N·m 持续 80 ms"检测触地，可以再加一条"由实测起跳速度算出的
预计落地时间"做超时兜底。

**怎么验**：固定窗口（+2 采样）连测 10 跳，出 `F0 → H` 散点，残差 < 15 mm 即可用。

**风险**：`VMC_JUMP_LENGTH_KP = 4500` 时实测关节峰值已到 36 N·m，相对 54 N·m 只有 1.5 倍
裕度，再加力会先撞关节限幅。所以这条要配 `airborne_joint_torque_max` 遥测一起看。

### P1-3 双腿协调补一点阻尼（kd）

aboard 的 leg sync 是纯 P（`kp 60, kd 0`，`vmc_probe.h:1072–1073`），注释里自己写了
"A pure-P tie (kd = 0) will ring at a stiff kp"。山海用的是
`PID_PositionCalcGivenDot`，即带速率项的 PD。差动模态的惯量 J_e ≈ 0.042 kg·m²，
用 ζ ≈ 0.7 反解 `kd ≈ 2ζ√(kp·J_e)`，kp = 60 时约 **0.6 N·m·s/rad**。改动一行，
风险极低，可以顺带做。

### P1-4 腾空姿态：从"腿竖直"改成"机体水平"（A/B）

**为什么**：aboard 现在空中只保留 θ/dθ 项（`vmc_probe.h:446` 起），即保持**腿竖直**；
报告 3.6.7 明确说他们优化后改成**保持机体水平**，理由是落地那一刻机体的姿态比
腿的姿态更决定冲击。物理上飞行中腿的摆动确实对机体有反力矩（风车自救就是靠这个），
所以"用 pitch/pitch_rate 项在飞行中稳住机体"是可行的。

**怎么验**：`airborne` 的 Tp 里把 pitch 项加回去（需一个开关），用 `jump_report.py`
对比落地瞬间的 pitch、pitch_rate 峰值和落地后 200 ms 内的恢复时间。

**风险**：飞行中腿的摆角会牺牲"伸腿落地"的空间。报告的做法是分两段：先保持水平，
落地前短暂等待再主动伸腿。我们的 `RETRACT(0.18) → LAND(0.23)` 已经是这个结构，
只是长度是固定值。

### P1-5 关节通道的"预测补偿"式增量 MPC（唯一有再次证伪风险的一项）

报告 3.3.2 的增量 MPC，读源码后会看到一个很关键的事实：**运行时它并不解 QP**。

```
K2_l[6..11] -= MPC_l[6..11];                      /* 先从 LQR 的腿行里减掉补偿增益 */
ΔTp = MPC_l[0..5] · Δx;                           /* 用状态增量算一步预测补偿 */
Tpl = K2_l·x - ΔTp;                               /* 只作用于 Tp，轮通道完全不动 */
```

无约束增量 MPC 的最优解本来就是状态的线性函数（`ΔU* = -K_mpc·x`），所以所谓的
"MPC" 在运行时退化成**一个按腿长调度的固定增益 + 一次状态预测**，12 次乘加就够。
系数 `MPC_p1..p12` 是离线（Simscape）算出来再按 L0 用双指数拟合的（源码里就是
`p1*exp(p2*L0) + p3*exp(p4*L0)`）。

对我们的意义：我们的 MPC 走的是"20 决策变量 + 显式速率/力矩约束 + QP"，所以贵
（1.1 ms），而且必须靠权限混控才能接管（而被证伪的正是混控）。报告的形态给了
第三条路：

- 只动关节通道，轮通道始终由 LQR 独占（轮通道是发散风险最高的一路）；
- 不做权限混合，用**硬开关**（开关瞬间把 u_prev 重新同步）；
- 用现有 `scripts/derive_vmc_lqr_abk.py` / `vmc_mpc_model.c` 的模型与权重，
  离线算无约束增益 `K_mpc(L0)`，拟合成 L0 的多项式（我们已有三次拟合的现成链路）；
- 限幅用输出级 clamp（±2 N·m 级别），而不是交给 QP 的约束。

这条路即使失败，代价也只是"关掉一个增益项"，不会像上次那样在 0.4 s 内失控。

### P2-1 把主机闭环 testbed 升级成"能预测真机"的仿真

**为什么**：报告用 Simscape 做了单腿和整车（单边桥/颠簸/坡道）两级仿真，
先仿真再上机。我们的 `tools/test_vmc_mpc.c` 是**线性被控对象自环**，而
`scripts/mpc_weight_sweep.py` 的注释已经诚实说明了它的局限：

> the plant in this test is the model itself ... the 2026-11-11 hardware baseline
> was a 105 mm slow cycle against ~14 mm here.

也就是说这个 testbed 判稳可以，预测绝对行为不行。而我们已经知道真机的主要
残余现象是 **5 s 周期、10 cm 量级的静摩擦极限环**。建议给它加三样东西（按性价比排序）：

1. **静摩擦/库仑阻尼模型**（stiction）：让 testbed 自己复现 105 mm/5 s 的慢循环。
   一旦能复现，静漂相关的任何改动都能先在主机上筛。
2. **接触/FN 模型**：轮-地法向力、离地、落地冲击，用于验证 P0-1 和 P1-1。
3. **VMC 非线性**（θ 依赖的雅可比、力限幅），否则大角度工况完全失真。

**怎么验**：以现有真机日志为基准，要求 testbed 在"静置 30 s 的 x 峰峰值""踢击后的
恢复时间"两项上落在真机 ±30% 内。

**风险**：这是投入最大的一项，不要一次做完；先做第 1 项，因为它直接指向我们
目前最痛的问题。

### P2-2 PSO / 自动整定（有条件再做）

报告用 PSO 调 R，适应度 = 轮力矩峰值与俯仰角峰值的 8:2 加权，30 粒子 × 100 代，
结果 **2.92 → 2.87 N·m（降 1.7%）**。收益很小，而且报告自己也说了"无法完全替代手动调参"。

结论：**现在不做**。等 P2-1 的 testbed 能复现真机行为之后再做，否则优化的是
一个跟真机不符的目标函数。真要做，比 PSO 更适合我们的是**日志驱动的参数回归**：
现有的 `tools/lqr_tuner` 网页 + RTT 已经能做到在线改 K/Q/R，配合
`slip_gate_replay.py` 那种"拿真机记录离线重算"的模式，比在模型里做黑箱搜索可靠。

### P2-3 功率与能源（报告第 5、6 章，本 PDF 未导出正文）

按目录和摘要，第 5 章是 FSBB 双向 DC-DC 恒功率控制器 + 超级电容组，
第 6 章是双边 LCC 无线充电。这两章是电源硬件工作，与我们的控制链路没有交集，

对 RoboMaster 而言：

- **恒功率取电 + 超级电容缓冲**：有直接价值。裁判系统功率限制下，跳跃和四关节

## 4. 不建议照搬的

这一节和上一节同样重要。以下七项在报告正文里权重很高，但**照搬会退化或错因**。

| 项 | 报告正文 | 为什么不要照搬 |
| --- | --- | --- |
| K(L0) 三次拟合 | 3.3.1.2 花了两页 | 我们已经在做（`vmc_lqr.c:27`），而且模型参数更全（gear_ratio、转子惯量、com_to_hip、轮粘性阻尼）。重做等于放弃现有标定。而且他们源码里 `ChangeK` 是关闭的 —— 真机跑的是固定 K + FN 门控。 |
| 质心偏移 θ_target(L0) 补偿 | 3.3.1.3，给了 4 点标定表 + 拟合 | 源码 `LQR_Clc()` 里 `Theta_Target_l=Theta_Target_r=0`，即最终**没有启用**。我们的静漂根因已经定位为**静摩擦极限环**，不是质心偏置（见 `docs/MPC分支工作总览_2026-11-06至11-12.md` §1）。按报告的因果去补偿，会治错病、还会引入腿长相关的新偏置。 |
| LQR 串增量 MPC（含权限混控） | 3.3.2，全章重点 | 实现思路可借（见 P1-5 的替代方案），但"混控"这一步我们已被实机证伪三次，其中一次 0.4 s 内失控；`vmc_probe.c:5281` 的注释给出了数学原因：权限 ramp 让 `u(k)` 的极点落在 z = a，Δu 增益被放大 1/(1−a)，90% 权限时是 9 倍。**永远不要在施加后的 u 上做权限混合。** |
| 打滑卡尔曼（R = diag(100, 1e6)） | 4.2.1 | 我们的体运动 KF 用实测噪声方差标定 Q/R 并做了 NIS 检验（`vmc_probe.h:512`），这是更正确的做法。报告那两个 R 是手调经验值，其中加速度通道 1e6 相当于几乎不信任 IMU，逻辑上说不通。 |
| 离地阈值 30 N（正文）/ 40 N（源码） | 3.6.4 | 我们的实测分离度是地面 65–80 N、空中 22–24 N，取 35 N + 1.7 释放比已经标定过（`vmc_probe.h:460–470`）。照搬 30 或 40 都会破坏现有分离度。 |
| 五连杆构型 | 第 2 章 | 工作空间和末端惯量的取舍不同，`串联腿电控核心方案对比.md` 已经论证过串联二连杆更适合我们的 0.18–0.385 m 行程。不要因为报告效果好看就换构型。 |
| 主动柔顺（改 TargetX） | 3.6.8 | 源码 `#ifdef ActiveCompliance` **关闭**。它的做法是"被推时把位移目标以 2 cm/s 拖走"，这在我们这里会和 anchor 重锚定、静摩擦极限环三者打架 —— 相当于给位置环加了一个慢积分。除非出现"顶住墙持续发散"的实测证据，否则不做。 |

## 5. 建议的实验顺序

| 步骤 | 内容 | 依赖 | 验收 |
| --- | --- | --- | --- |
| 0 | **实测轮距 Rl** | 无 | 一个数，两个功能同时解锁（打滑判据 A、P0-4） |
| 1 | P0-1 龙伯格观测器 | 无 | 离线回放：FN 方差下降、落地 FN 更低、穿阈次数不增 |
| 2 | P1-1 碰撞力 Ft + 上台阶并行判据 | 1 | 回放历史台阶日志：两判据触发时刻差 < 100 ms，无平地误触发 |
| 3 | P0-2 + P0-4 差动力合成（roll PD + 离心前馈） | 0 | 单边桥 roll 峰值下降；低速 v·ω 工况 roll 下降 |
| 4 | P0-3 偏航双环 + 内环限幅 | 0 | spin 电流抖动下降；阶跃转向超调下降 |
| 5 | P1-3 leg sync 加 kd | 无 | 长腿短腿各一次侧向敲击，差动模态不振荡 |
| 6 | P1-4 飞行姿态 A/B + P1-2 高度标定 | 无 | `jump_report` 10 跳：H 残差 < 15 mm，落地 pitch 峰值下降 |
| 7 | P1-5 关节通道"预测补偿"式 MPC（影子先行） | 1 | 影子与 LQR 偏差 < 5 N·m；再考虑硬开关（**不要 ramp 混控**） |

### 关于第 7 步（P1-5）的提醒

这是唯一有"再次证伪"风险的一项，也是唯一需要新写离线生成链路的。**必须影子先行**：
先只计算不输出，记录影子 Tp 与 LQR Tp 的偏差；偏差稳定在 5 N·m 以内、且不随腿长
跳变，才允许硬开关接管。**不要再做权限 ramp**——上次失控的数学原因写在
`vmc_probe.c:5281` 的注释里，而报告的形态恰好没有混控这一步。

## 7. 一句话总结

**不用改架构，也不该改架构。** aboard 的控制骨架（VMC + LQR + LESO + 事件门控 + 遥测）
比报告成熟，报告的增量 MPC、K 调度、质心补偿在它自己的源码里都没能留下来。

真正值得吸收的是它**把力算出来再用力做判断**的习惯：二阶微分观测器 → 支撑力 FN →
碰撞力 Ft → 离地/上台阶/跳跃的触发，以及**把翻滚和偏航拆成"慢的位置通道 + 快的力通道"**
这两处结构。加起来大概 300 行代码、四组参数，而且大部分可以在日志回放里验证完
再上机。
