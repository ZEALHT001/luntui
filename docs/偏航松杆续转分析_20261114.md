# 松杆后继续转向：2026-11-14 采集分析

采集：`logs/slip_20261114_021322`（150 s，双流，VMCVOFA 48.15 Hz / VMCFAST 217 Hz，
覆盖率 96%，中途 J-Link 重连一次，最大缺口 4.7 s）。

结论先行：**不是摇杆残留，是航向目标积分饱和（windup）。** 摇杆以 1.8 rad/s 积分
航向目标，而偏航轴实际只能做到 0.4–0.9 rad/s，多出来的部分记成"欠账"；松杆后目标
停住，机器人必须把这笔欠账转回来，所以看起来"松了还在往最后打杆的方向转"。

## 1. 摇杆中位是干净的

| 量 | 值 |
|---|---|
| `turn_stick` 中位 / p90 / p10 | 2 / 3 / 2（满量程 ±700） |
| 落在 ±20 死区内的帧 | 87.4% |

中位 2 counts，远小于 `VMC_RC_CH_DEADBAND = 20`，所以**不是中位偏移**在让目标漂移。

## 2. 目标跑得比机器人快

| 区间 | 摇杆 | `d(yaw_error)/dt` | 说明 |
|---|---|---|---|
| 43.3→44.3 s | +700（满杆） | **+0.88 rad/s** | 目标以 1.8 rad/s 前进 |
| 50.3→51.3 s | +700（满杆） | **+1.19 rad/s** | 同上 |
| 52.3→58.3 s | +2（已松杆） | **−0.43 rad/s** | 松杆后仍以 0.43 rad/s 转回来 |

松杆瞬间的欠账是 **3.13 rad（179°）**，按 0.43 rad/s 需要约 6 s 才能转回来——这
就是"松杆后继续转"的直接来源：一次 2 s 的打杆，换 6 s 的回转。

## 3. 偏航轴本身饱和

稳态（66–149 s，摇杆中位）：

| 量 | 值 |
|---|---|
| `yaw_error` | 0.16 rad 长期不收敛 |
| `yaw_rate_cmd`（182） | 1.6 rad/s 长期输出 |
| `body_yaw_rate` | ≈ 0 |
| 轮速 L/R | −0.05 / +0.04 rad/s |

即：控制器连续 80 s 要求 1.6 rad/s，机器人在原地不动。这说明在 1.6 rad/s 对应的
差动电流下，偏航力矩还不足以克服轮胎横向刮擦（静摩擦死区）；只有欠账足够大、
182 撞到 ±2.5 的限幅（全程 12% 的帧）时才开始转。

即 **外层角速度指令的可达上限远低于 2.5 rad/s**，而摇杆积分用的是 1.8 rad/s，两者
不匹配是根因。

## 4. 双环本身工作正常

- 181 与 182 相等 → spin 前馈为 0，符合非 spin 工况；
- 181 = 10 × 184 逐帧成立 → 外环 `kp_outer = 10` 生效；
- 182 撞 ±2.5 的帧占 12%，限幅确实在起作用（不是没生效，而是**经常顶死**）。

## 5. 有待确认的一项

遥测里看不到**实际施加的偏航差动电流**：慢流 60/61 字段发的是平衡环的电流
（`left_wheel_current_send`，不含偏航项），快流 `wheel_*_current_output` 是含偏航项
的最终值但只有 250 Hz 采样、与 450 Hz 的环路相位不对齐，两者相减得到的偏航电流在
±100–400 counts 之间抖，无法直接判断"到底施加了多少"。

因此"偏航轴为什么只做到 0.43 rad/s"当时只能从**速率**反推，不能从**电流**证实。

**已解决**：`vmc_wheel_control.yaw_hold_current` 现在发在保留槽 185（采集 CSV 里是
`descent_trigger_count` 这一列）。下一轮采集可以直接看：182 要求 2.5 时 185 是否
≈2500 → 环路的电流确实施加了，问题在偏航力矩/刮擦；185 明显偏小 → 环路没把电流送
出去（那就是代码问题）。

## 6. 建议的修复方向

1. **目标积分防饱和**（必须）：每个周期把 `yaw_target - yaw` 限制在 ±`yaw_lead_max`
   （建议 0.35 rad ≈ 20°）。任何打杆最多积 20° 的欠账，松杆后 ≤1 s 就能收敛。
2. **摇杆角速度前馈**（推荐）：非 spin 模式下，把 `turn_input × yaw_target_rate_max`
   直接加到内环角速度指令上（和 spin 前馈同一位置、同样加在限幅之后）。这样打杆
   期间机器人是在跟"角速度指令"，角度环只负责收尾，欠账根本不会产生。
3. **补遥测**：`yaw_hold_current` 放 185，用一轮短采集确认偏航电流的实际量级；
   确认是力矩不足后，`yaw_hold_kd` 已从 1000 提到 **2000**（上限 20000 还有余量）。

## 7. 已实施的修改

按上面的方案 1+2 实现（提交见 git log）：

- `vmc_yaw_target_advance()`：目标推进后把 `yaw_target - yaw` 夹在 ±`yaw_lead_max`
  （默认 0.35 rad）；
- 非 spin 模式下 `yaw_stick_rate = turn_input * yaw_target_rate_max` 作为内环角速度
  前馈（遥测 183）；
- 新增运行参数 `yaw_lead_max`（0–3.15 rad，tuner 可调）。

## 8. 修复后复测（2026-11-14 02:27，`logs/slip_20261114_022710`）

90 s，覆盖率 99.9%，无重连。**摇杆中位是干净的、185 与 182 的相关性 0.94**，所以这
一轮同时定案了"环路到底有没有施加电流"。

| 指标 | 修复前（02:13） | 修复后（02:27） |
|---|---:|---:|
| 松杆瞬间的航向欠账 | 3.13 rad（179°） | **0.340 rad（19.5°）**，被 `yaw_lead_max` 压住 |
| 打杆时实际偏航角速度 | 0.4–0.9 rad/s | **峰值 2.54 rad/s**，长时间打杆均值 1.1–1.7 |
| 松杆后回到 \|wz\| < 0.05 的时间 | ≈6 s | **中位 0.17 s，最慢 0.34 s**（31 次打杆） |
| 实际施加的偏航电流 185 | 不可见 | 峰值 **+3969 / −2998** counts |

**定案结论**：`yaw_hold_current` 与理论值 `1000 × (182 + 183 − wz)` 的比值中位数
**1.000**（32 个采样窗口）。也就是说：

- 环路**确实**把算出来的电流送到轮子上了，没有代码路径丢失；
- 02:13 那次"要求 1.6 rad/s 却原地不动"，是**偏航轴力矩不足**（轮胎横向刮擦吃掉），
  不是环路没施加；
- 现在能转到 2.5 rad/s，是因为摇杆角速度前馈让内环直接跟踪 1.8 rad/s 的指令，再加上
  外环在 0.35 rad 提前量内提供的修正，总指令能到 4.3 rad/s（电流约 4300 counts），
  足以克服刮擦。
