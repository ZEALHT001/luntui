# A 板硬件配置

## 项目定位

- A 板是底盘控制板，负责轮腿底盘 VMC/LQR 控制、腿部关节控制、轮电机控制和与 C 板板间通信。
- 当前 A 板与 C 板之间通过 CAN 通信；A 板使用 CAN2，C 板使用 CAN1。
- 新遥控器使用 FS-i6S SBUS 接收机，接在 A 板 USART1；SBUS 已成为 A 板的主遥控输入。

## CAN 总线分配

| 总线 | 设备 / 用途 |
| --- | --- |
| CAN1 | 左右轮电机反馈和电流控制、右前/右后达妙关节 |
| CAN2 | A/C 板间通信、左前/左后达妙关节 |

## 轮电机配置

| 设备 | CAN 总线 | 反馈帧 ID | 命令帧 ID | 说明 |
| --- | --- | --- | --- | --- |
| 左轮电机 | CAN1 | 0x201 | 0x200 | DJI 电机反馈格式 |
| 右轮电机 | CAN1 | 0x202 | 0x200 | DJI 电机反馈格式 |

## 腿部关节电机配置

| 设备 | CAN 总线 | 反馈帧 ID | 命令帧 ID |
| --- | --- | --- | --- |
| 右后关节 | CAN1 | 0x003 | 0x004 |

## 板间通信协议

| 方向 | A 板总线 | C 板总线 | 标准帧 ID | 数据格式 |
| --- | --- | --- | --- | --- |
| A 板 -> C 板 | CAN2 | CAN1 | 0x310 | 8 字节魔术帧 |
| C 板 -> A 板 | CAN2 | CAN1 | 0x311 | 8 字节魔术帧 |

- Payload 固定格式：`0xA5, 0x5A, SRC, DST, seq_l, seq_h, tick_l, checksum`。
- A 板发送 `SRC='A', DST='C'`；A 板接收并校验 `SRC='C', DST='A'`。
- `checksum` 是前 7 个字节的 XOR。
- 只有 CAN ID、SRC/DST、魔术字、checksum 全部匹配时，才增加 `board_comm_state.rx_success_count`。
- A 板板间通信 LiveWatch 全局变量：`board_comm_state`。

## 主要 LiveWatch 变量

| 变量 | 用途 |
| --- | --- |
| `vmc_probe_state` | 底盘电机反馈、腿部状态、VMC/LQR 状态和安全状态 |
| `vmc_control` | 腿长和腿部 VMC 控制参数 |
| `vmc_wheel_control` | 轮电机电流输出状态 |
| `vmc_balance` | 平衡控制参数、LQR 分项、Yaw hold 状态 |
| `remote_control` | 当前生效的新遥控 0..9 归一化通道和接收状态 |
| `sbus_remote_data` | SBUS 原始/归一化 16 通道、启动校验、在线/失控/丢帧状态和接收计数 |
| `hi12_imu` | IMU 姿态、角速度、加速度和接收状态 |
| `board_comm_state` | A/C 板间通信发送、接收、校验和在线状态 |

USART1 收到的 25 字节数据会送入 `sbus_remote_data`，通过启动安全校验后再复制到
`remote_control` 作为主控制输入。18 字节 DBUS 分支仍保留，但不再参与控制。

## 新遥控通道与启动安全

通道下标均指 `sbus_remote_data.normalized[]` / `remote_control.normalized[]`：

| 下标 | 功能 | `-1` | `0` | `+1` |
| --- | --- | --- | --- | --- |
| 0 | 左摇杆横向：底盘转向 | 左 | 中位 | 右 |
| 1 | 左摇杆纵向：底盘前后 | 下 | 中位 | 上 |
| 2 | 右摇杆纵向：云台前后 | 下 | 中位 | 上 |
| 3 | 右摇杆横向：本地 SBUS Roll | 左高右低 | 回正 `roll=0` | 左低右高 |
| 4 | 启动 / 急停 | **急停、全部功能失能** | — | 允许使能 |
| 5 | 小陀螺模式 | 禁用 | — | 启用 |
| 6 | 跳跃模式 | 禁用 | 自动跳 | 手动跳一次 |
| 7 | 自动上台阶 / 下平台 | 禁用 | — | 启用 |
| 8 | 普通模式最大速度 / 小陀螺转速 | 速度 `0%` / 旋转 `0 rad/s` | 速度 `50%` / 旋转 `4.5 rad/s` | 速度 `100%` / 旋转 `9 rad/s` |
| 9 | 腿长 | 最短 `0.170 m` | 线性中点 `0.265 m` | 长腿 `0.360 m` |

腿长旋钮不产生额外的离散档位，而是先连续换算目标腿长；需要判断原低/中/高档的
逻辑时，直接比较换算后的目标值：

| 档位逻辑 | 旋钮目标腿长条件 |
| --- | --- |
| 低档 | `>= 0.170 m` |
| 中档 | `>= 0.260 m` |
| 高档 | `>= 0.360 m` |

比较时保留 `0.0005 m` 的量化容差，等价于旋钮目标值达到旧档位值。
当前全部软件腿长下限统一为 `0.170 m`：`VMC_LEG_LENGTH_MIN`、短腿目标、
通道 9 旋钮最低值、自起站立、上台阶收回和跳跃压缩目标都使用或高于该值。
实测机械硬限位仍为 `0.160 m`，软件保留 `10 mm` 安全余量。

启动后，SBUS 必须连续约 200 ms 满足以下条件，控制数据才会标记为有效：

- 通道 0..3 都在 `0 ± 0.03` 内；
- 通道 4、5、6、7 都在 `-1 ± 0.03` 内；
- 通道 9 腿长旋钮换算后的目标腿长必须严格小于 `0.220 m`，不再要求一定在最上档；
- 通道 8 速度旋钮不参与启动合格检查，可以在任意位置；
- 帧不处于 failsafe 或 frame-lost 状态。

若启动过程中任一帧不满足，`sbus_remote_data.startup_rejected` 会置 1，
`valid` 保持 0，关节和轮输出都不能使能。此时必须手动把通道 4、5、6、7
全部打回最上档 `-1`、通道 9 调整到腿长小于 `0.220 m`、通道 0..3 全部回中，
并**连续保持超过 5 秒**；通道 8 可以保持任意位置。中途任一帧离开
该姿态会重新计时。满足后 `startup_rejected` 清除，`valid` 变为 1。可通过
`sbus_remote_data.startup_reject_reason` 查看原因：bit0 摇杆不在中位，bit1
开关/旋钮不在 `-1`，bit2 启动帧异常；恢复进度看
`sbus_remote_data.recovery_hold_ms`。

正常运行中，通道 4 打回上档 `-1` 会立即急停并禁用通道 5/6/7 对应的功能；
通道 8 回到 `-1` 时最大速度倍率为 0。通道 2/3 当前只在 A 板保存为
`remote_control.normalized[2/3]`，尚未通过板间协议下发给 C 板云台。

通道 5 下档启用小陀螺时，通道 8 只控制旋转目标，不再限制前进速度：

- 最低 `-1`：`0 rad/s`
- 中点 `0`：`4.5 rad/s`
- 最高 `+1`：`9 rad/s`

实际值保存在 `vmc_balance.yaw_spin_rate`，最大值参数为
`vmc_balance.yaw_spin_rate_max`（默认 `9.0 rad/s`）。关闭小陀螺后重新锁定当前航向。
小陀螺前进速度直接由左摇杆幅值映射到 `0～3 m/s`；退出小陀螺后，通道 8
重新作为普通模式最大前进速度倍率。

速度目标斜坡按模式分开：

- 普通模式：`vmc_balance.speed_ramp_rate = 2.25 m/s²`
- 小陀螺模式：`vmc_balance.spin_speed_ramp_rate = 4.5 m/s²`

小陀螺前进采用连续幂律投影，不再使用固定角度窗口：

- 开启通道 5 的瞬间，用 IMU 当前 Yaw 锁存世界坐标基准 `spin_line_origin_yaw`；
- 小陀螺模式下，左摇杆 `X/Y` 合成为二维方向向量，`atan2` 后叠加到基准朝向，得到目标世界方向 `spin_line_yaw`；
- 世界方向再叠加轨迹补偿 `vmc_balance.spin_line_path_offset_deg`，默认 `-75°`；
  这是为了抵消当前样机的累计左偏；设为 `0` 可关闭补偿；
- 摇杆幅值 `sqrt(X²+Y²)` 控制移动速度，因此可以向左前、右前、正左、正右等方向近似移动；
- 车体继续按通道 8 的转速旋转；
- 推进增益使用连续幂律：

```text
phase = heading_error + phase_lead
gain  = sign(cos(phase)) × |cos(phase)|^power
```

- 默认幂律指数 `vmc_balance.spin_line_projection_power = 5.0`；
- 相位超前按小陀螺转速补偿速度斜坡造成的跟踪滞后：

| 小陀螺转速 | 相位超前 |
|---:|---:|
| `1 rad/s` | `0°` |
| `2 rad/s` | `11°` |
| `3 rad/s` | `20°` |
| `4 rad/s` | `25°` |
| `5 rad/s` | `30°` |
| `6 rad/s` | `33°` |
| `7 rad/s` | `35°` |
| `8 rad/s` | `37°` |
| `9 rad/s` | `39°` |

- 中间转速按分段线性插值；
- `vmc_balance.spin_line_gate` 是连续有符号投影增益（-1..1），正数正向驱动、负数反向驱动；
- `vmc_balance.spin_line_phase_lead_rad` 为当前相位超前；
- `vmc_balance.spin_line_phase_error` 为当前相对目标方向的误差；
- `vmc_balance.spin_line_input_forward`、`spin_line_input_lateral` 和
  `spin_line_input_magnitude` 为当前左摇杆方向向量；

该模式只能保证“大致沿世界方向”，无法抵消轮胎侧滑和长期横向漂移；需要严格直线时应关闭小陀螺。

当 SBUS 直接连接 A 板且通道 4 已使能时，右摇杆横向轴（通道 3）切换为 Roll
控制；左摇杆通道 0/1 继续负责底盘转向和前后运动：

- 向左摇：`roll_target < 0`，机身左高右低；
- 回中：`|normalized[3]| <= roll_remote_deadband` 时 `roll_target = 0`；
- 向右摇：`roll_target > 0`，机身左低右高；
- 最大目标角由 `vmc_control.roll_remote_target_max` 控制，默认 `0.50 rad`；
- 死区由 `vmc_control.roll_remote_deadband` 控制，默认 `0.03`；
- LiveWatch 可用 `vmc_balance.roll_remote_active` 确认该轴当前是否由本地 SBUS 接管。

左摇杆横向通道 0 的底盘转向方向已单独反转，不影响右摇杆通道 3 的 Roll 方向。

## 自动跳跃触发条件

通道 4 下档使能、通道 6 中档选择自动跳跃后，满足以下条件会自动触发：

| 条件 | 阈值 | 来源 |
| --- | --- | --- |
| 跳跃模式 | 中档 | `remote_control.normalized[6]` |
| 车体速度 | ≥ 1.5 m/s | `vmc_probe_state.motion.kf_dx`（融合实测速度，取绝对值） |
| TF02 激光测距 | 90 cm < 距离 < 110 cm（两端开区间） | `tf02_distance_cm` |

补充说明：

- 速度用的是**实测融合速度** `kf_dx`，不是摇杆给定值；要求车真的在跑。
- 激光必须**在线**（`tf02_connected != 0`）。连续 100 ms 收不到帧就判离线，此时不会触发跳跃。
  若 TF02 没接或没工作，自动跳跃永远不会触发。
- 三个条件需连续保持 `jump_auto_confirm_ms`（默认 20 ms，约 9 个控制周期）才点火，
  避免单帧激光或速度尖峰误触发。
- `jump_armed` 现在表示“自动门已满足、即将点火”，可用于观察。
- 原有的姿态门限、反馈超时门限、阶段超时、落地冷却和后空翻中止逻辑全部保留不变。

**这四项都可以在 LQR 调参网页上实时改，不需要烧录**（“自动跳跃门控”分组）：

| 网页字段 | 固件字段 | 默认值 |
| --- | --- | --- |
| 触发速度下限 | `jump_auto_speed_min` | 1.5 m/s |
| 测距下限（不含） | `jump_auto_dist_min_cm` | 90 cm |
| 测距上限（不含） | `jump_auto_dist_max_cm` | 110 cm |
| 条件确认时间 | `jump_auto_confirm_ms` | 20 ms |

固件在写入时会把距离上下限规范化，所以先发上限再发下限也不会留下一个“永远不满足”的区间。
`App/Inc/vmc_probe.h` 里同名的宏只是上电默认值。

通道 6 位置语义：

| 通道 6 | 行为 |
| --- | --- |
| 上档 `-1` | 禁用跳跃 |
| 中档 `0` | 自动跳跃；条件满足即起跳 |
| 下档 `+1` | 手动跳一次；必须离开下档再回下档才能再次触发 |

自动跳跃结束后，需要先把通道 6 打回上档禁用，再回中档，才能进行下一次自动跳跃。

## 自动上台阶（撞击收腿）

- 仅在通道 4 使能、通道 7 下档启用、通道 9 达到高档 `>= 0.360 m` 且实测腿长达到准备长度时参与。
- 操作方式：通道 7 打向下档，通道 9 旋到高档，向前撞上比机身低的平台。车轮被挡住后 LQR 会持续要求轮力矩，同时腿被平台顶回，这两个特征同时成立才判定撞击。
- 触发条件：平均腿长达到 `stair_ready_length` 并保持、存在前进指令、轮速达到 `stair_speed_threshold` 并保持、先经过低速变化窗口预武装，然后左右两条腿都满足
  `|轮力矩指令| >= stair_impact_torque_threshold` 且
  `|腿摆角 theta| >= stair_impact_theta_threshold`，并持续 `stair_impact_confirm_ms`。
- 触发后进入 `RETRACT`：目标腿长切到软件最短 `stair_retract_length`（默认 `0.17 m`），同时两条腿的绝对摆角 `phi0` 以 `stair_phi0_ramp_rate`（默认 `4 rad/s`）斜坡到 `stair_phi0_target`（默认 `2.5 rad`）。这一步直接接管腿部 `phi0` PD，不再用 `theta_target` 间接摆腿。首轮 10 rad/s + `kp/kd=50/0.5` 实测冲到约 `2.85 rad` 且轮端前冲明显，因此上台阶专用 PD 默认改为 `kp=120`、`kd=6`，不再复用普通 phi0 增益。测得平均腿长到达目标，或 `stair_retract_timeout_ms`（默认 `250 ms`）到期后进入 `HOLD`，保持 `stair_hold_ms` 后完成。HOLD 阶段不再固定保持 phi0=2.5，而是按同一斜坡把 phi0 回收到正常站立目标，避免已经上台阶后还锁着前倾姿态继续跑。实测台阶会挡住轮子，腿长不一定能收到 0.17 m，所以必须保留时间兜底。
- 完成后机器人保持短腿，直到通道 9 旋钮移动并稳定，避免机身还在台阶上时腿长又弹回长腿目标。
- 自起、跳跃、反馈超时、遥控失能都会中止动作。**腾空 latch 不会中止上台阶**，因为收腿越过台沿时轮子天然会短暂离地；轮输出仍按原有安全门控关闭，落地后恢复。总超时为 `stair_timeout_ms`，再次触发冷却为 `stair_cooldown_ms`。
- `stair_preimpact_diff_max` 是预武装的低加速度门控，`0` 表示关闭。首轮实测表明原始轮速差分在 450 Hz 下量化尖峰很大，`0.6 m/s²` 会让预武装几乎永远攒不满；关闭后由已经确认的高速轮速窗口负责预武装。
- 所有 `stair_*` 参数都可通过 RTT / 调参网页实时修改；VOFA 字段 157..173 提供状态、触发进度、轮速特征、左右腿撞击标志和速度/预武装/撞击确认计时。字段 174..176 追加 `rc_source`、`remote_s1`、`remote_s2`；新遥控下 `rc_source=3`，`remote_s1` 由通道 4 合成。

## 自动下平台（空中伸腿与落地缓冲）

- 仅在通道 4 使能、通道 7 下档启用，且通道 9 达到高档或刚刚完成自动上台阶、仍保持短腿锁定时启用。
- 离台检测优先使用整机离地候选的短确认窗口 `descent_start_confirm_ms`（默认 `40 ms`），不必等待普通离地 latch 的 `100 ms` 确认。没有上台阶锁定时还要求实际行驶速度超过 `descent_start_speed`，避免把人工抬起误判为下平台。
- `EXTEND` 阶段目标腿长以 `descent_extend_rate`（默认 `0.35 m/s`）斜坡伸向 `descent_extend_length`。如果离台前腿长已经高于该值，则至少再伸长 `20 mm`，并受机械上限约束。空中使用独立的 `descent_kp_length`、`descent_kd_length`、`descent_max_force` 和 `descent_support_force`，默认支撑前馈为 `0`，避免伸腿动作本身被误当成触地负载。
- 平均绝对关节力矩超过 `descent_contact_torque` 并保持 `descent_contact_confirm_ms`（默认 `20 ms`）后确认触地。进入 `CUSHION` 的同一控制周期立即恢复轮平衡输出，不再等待普通离地检测的 `500 ms` 释放滞回。
- `CUSHION` 阶段以 `descent_return_rate`（默认 `0.60 m/s`）把双腿目标收回到离台前实测腿长，吸收落地冲击；收回完成或到达 `descent_cushion_timeout_ms` 后结束。空中超时则中止，由普通离地检测重新接管轮输出安全门控。
- `descent_*` 参数均可通过 RTT / 调参网页实时修改。VOFA 字段 177..186 记录下降阶段、中止原因、触地标志、离台长度、空中目标、斜坡目标、触地力矩、触地耗时和触发/中止计数。

## 跟随接地伸长（可选）

默认**关闭**，可在调参网页「跟随接地伸长」分组实时开关与调参。

开启后：某条腿一旦**不承重**（复用离地检测的单侧 latch），它的腿长目标就以
`leg_follow_rate` 向外跟随，配合原有的支撑前馈把轮子重新压回地面；直到目标到达
**0.385 m 行程上限**才停止伸长。到顶之后再抬升，轮子才真正离地，此时由离地检测接管。
该腿重新承重后，额外的伸长量以 `leg_follow_return_rate` 回到档位值，避免每次抬升都把
站立高度往上棘轮。

关闭该功能时，腿长环保持通道 9 的腿长目标：被抬升会被当成位置偏差，产生回缩力把轮子往机身
方向拉，所以腿在到达行程上限之前就停止跟随。

| 参数 | 默认 | 说明 |
| --- | ---: | --- |
| `leg_follow_enable` | 0 | 使能，默认关闭 |
| `leg_follow_auto_scope` | 1 | 按 roll 方向自动选择触发范围（见下） |
| `leg_follow_machine_wide` | 1 | 固定触发范围，仅在 `auto_scope=0` 时生效 |
| `leg_follow_roll_deadband` | 0.10 rad | 水平死区，约 5.7° |
| `leg_follow_scope_confirm_ms` | 250 ms | 低侧判定需保持多久才被采信 |
| `leg_follow_episode_timeout_ms` | 3000 ms | 脱空事件在无 latch 后的最长存活时间 |
| `leg_follow_rate` | 0.20 m/s | 脱空时目标外伸速率 |
| `leg_follow_return_rate` | 0.05 m/s | 重新承重后回位速率 |

前提：该功能的"脱空"判据来自离地检测的单侧 latch，所以**离地检测必须处于使能状态**
（`airborne_detect_enable = 1`），否则该功能不会动作。

### 伸长哪条腿：永远伸【低侧】

判定依据是**机身朝哪边倾**，不是"哪条腿脱空" —— latch 只是症状。

| 处境 | 低侧 | 伸低侧的效果 |
| --- | --- | --- |
| 一侧掉下平台 | 掉下去那条 | 够到低处的地面 |
| 平地抬起一侧 | 着地那条 | 把机身整体顶起来 |

两种情况**动作相同**，所以不需要"抬起/掉落"分类器 —— 只需要可靠地读出哪边低。这同时让未判定
窗口变得安全：伸低侧不可能把机身撬下平台，最坏情况只是"暂时没伸"。

> **这里换过一次设计。** 上一版按「脱空侧在 roll 的**高**侧 → 被抬起 → 双腿伸长」判定，实测
> 失败：把一侧推下平台时，**平台侧**那条腿会先失去负载（力矩瞬间掉到 1.9 N·m，刚好低于 2.0
> 的置位阈值，持续 120 ms），而它几何上就在高侧。于是"掉落"被读成"被抬起"，两条腿一起伸，
> 把机身继续撬向掉落侧 —— 最终两腿都顶到行程上限、roll 到 38.7°，仍然没有够到任何东西。
>
> `body.roll` 为正表示**右侧偏高**，所以低侧映射为：`roll > +deadband` → 左侧低，
> `roll < -deadband` → 右侧低，死区内 → 读不出。

**单帧不作为证据。** 一次判定必须持续 `leg_follow_scope_confirm_ms`（默认 250 ms）才被采信；
候选一变（包括变成"水平"）计时清零重来。定下后**锁住**，直到本次事件结束 —— 因为本功能自己的
伸腿动作会把机身推过水平位置。

未判定期间只对**既脱空、又处在低侧**的那条腿伸长，构造上不会去推高侧。

`leg_follow_machine_wide`（固定双腿/单腿）现在**只在 `auto_scope=0` 时生效**，保留它是为了能
不改固件做对照实验。

### 事件为何要比 latch 活得久

跟随伸腿会**抬高关节力矩**，而它等待的正是同一个力矩 latch —— 于是形成一个自我拆台的循环：

```
伸腿 → 力矩上升 → 越过释放阈值 → latch 掉 → 伸长量回退 → 力矩下降 → latch 再置位 → 又伸
```

实测这一循环周期约 1 秒：一次只伸出去约 **14 mm** 就释放，然后回退 **102 mm**，反复两次，始终
攒不出足够的伸出量去够到任何东西。

因此**脱空事件的存活时间独立于 latch**：

- 机身还倾着（`|roll| > deadband`）时事件保持，伸长量**保持并继续追**，不回退；
- 机身回到水平后事件结束，伸长量按 `leg_follow_return_rate` 回位；
- `leg_follow_episode_timeout_ms`（默认 3000 ms）是兜底：如果一直不回平（比如机器停在平台边上），
  超时后照样回位，避免无限保持。

判定完成后，**锁定的低侧那条腿在整个事件期间持续追**，即使它的 latch 已经掉线 —— 够地本来
就是目的，而 latch 在腿开始推的时候必然会掉。
