# A 板硬件配置

## 项目定位

- A 板是底盘控制板，负责轮腿底盘 VMC/LQR 控制、腿部关节控制、轮电机控制和与 C 板板间通信。
- 当前 A 板与 C 板之间通过 CAN 通信；A 板使用 CAN2，C 板使用 CAN1。
- 遥控器 DT7 当前安装在 C 板；A 板此前临时接过 DT7 用于底盘调试。

## 板间通信协议

| 方向 | A 板总线 | C 板总线 | 标准帧 ID | 数据格式 |
| --- | --- | --- | --- | --- |
| A 板 -> C 板 | CAN2 | CAN1 | 0x310 | 8 字节魔术帧 |
| C 板 -> A 板 | CAN2 | CAN1 | 0x311 | 8 字节魔术帧 |

- Payload 固定格式：`0xA5, 0x5A, SRC, DST, seq_l, seq_h, tick_l, checksum`。
- A 板发送 `SRC='A', DST='C'`；A 板接收并校验 `SRC='C', DST='A'`。
- `checksum` 是前 7 个字节的 XOR。
- 只有 CAN ID、SRC/DST、魔术字、checksum 全部匹配时，才增加 `board_comm_state.rx_success_count`。
- A 板板间通信 LiveWatch 全局变量：`board_comm_state`。

## 自动跳跃触发条件

跳跃由三个条件同时满足后**自动触发**，不再需要拨 S1 点火：

| 条件 | 阈值 | 来源 |
| --- | --- | --- |
| 遥控器 S1 | `RC_SW_UP`（= 1） | `remote_control.s[1]` |
| 车体速度 | ≥ 1.0 m/s | `vmc_probe_state.motion.kf_dx`（融合实测速度，取绝对值） |
| TF02 激光测距 | 80 cm < 距离 < 100 cm（两端开区间） | `tf02_distance_cm` |

补充说明：

- 速度用的是**实测融合速度** `kf_dx`，不是摇杆给定值；要求车真的在跑。
- 激光必须**在线**（`tf02_connected != 0`）。连续 100 ms 收不到帧就判离线，此时不会触发跳跃。
  若 TF02 没接或没工作，自动跳跃永远不会触发。
- 三个条件需连续保持 `jump_auto_confirm_ms`（默认 20 ms，约 9 个控制周期）才点火，
  避免单帧激光或速度尖峰误触发。
- `jump_armed` 现在表示“自动门已满足、即将点火”，可用于观察。
- 原有的姿态门限、反馈超时门限、阶段超时、落地冷却和后空翻中止逻辑全部保留不变。

**这四项都可以在 LQR 调参网页上实时改，不需要烧录**（“自动跳跃门控”分组）：

| 网页字段 | 固件字段 | 默认值 |
| --- | --- | --- |
| 触发速度下限 | `jump_auto_speed_min` | 1.0 m/s |
| 测距下限（不含） | `jump_auto_dist_min_cm` | 80 cm |
| 测距上限（不含） | `jump_auto_dist_max_cm` | 100 cm |
| 条件确认时间 | `jump_auto_confirm_ms` | 20 ms |

固件在写入时会把距离上下限规范化，所以先发上限再发下限也不会留下一个“永远不满足”的区间。
`App/Inc/vmc_probe.h` 里同名的宏只是上电默认值。

S1 位置语义：

| S1 | 行为 |
| --- | --- |
| UP（1） | 允许驱动 + **使能自动跳跃**；条件满足即自动起跳 |
| MID（3） | 正常驱动，不触发跳跃 |
| DOWN（2） | 急停，控制器失能 |

一次跳跃结束（FINISHED/ABORT）后状态会停在原地，需要把 S1 拨回 MID 再回 UP 才能进行下一次，
这是刻意的“每次跳跃显式确认”。

## 自动上台阶（撞击收腿）

- 仅在 **S2 最高档腿长** 下使能；S2 中、低档完全不参与。
- 操作方式：S2 打到最高档，向前撞上比机身低的平台。车轮被挡住后 LQR 会持续要求轮力矩，同时腿被平台顶回，这两个特征同时成立才判定撞击。
- 触发条件：平均腿长达到 `stair_ready_length` 并保持、存在前进指令、轮速达到 `stair_speed_threshold` 并保持、先经过低速变化窗口预武装，然后左右两条腿都满足
  `|轮力矩指令| >= stair_impact_torque_threshold` 且
  `|腿摆角 theta| >= stair_impact_theta_threshold`，并持续 `stair_impact_confirm_ms`。
- 触发后进入 `RETRACT`：目标腿长切到机械最短 `stair_retract_length`（默认 `0.16 m`），同时两条腿的绝对摆角 `phi0` 以 `stair_phi0_ramp_rate`（默认 `4 rad/s`）斜坡到 `stair_phi0_target`（默认 `2.5 rad`）。这一步直接接管腿部 `phi0` PD，不再用 `theta_target` 间接摆腿。首轮 10 rad/s + `kp/kd=50/0.5` 实测冲到约 `2.85 rad` 且轮端前冲明显，因此上台阶专用 PD 默认改为 `kp=120`、`kd=6`，不再复用普通 phi0 增益。测得平均腿长到达目标，或 `stair_retract_timeout_ms`（默认 `250 ms`）到期后进入 `HOLD`，保持 `stair_hold_ms` 后完成。HOLD 阶段不再固定保持 phi0=2.5，而是按同一斜坡把 phi0 回收到正常站立目标，避免已经上台阶后还锁着前倾姿态继续跑。实测台阶会挡住轮子，腿长不一定能收到 0.16 m，所以必须保留时间兜底。
- 完成后机器人保持短腿，直到 S2 换到另一个稳定档位，避免机身还在台阶上时腿长又弹回最高档。
- 自起、跳跃、反馈超时、遥控失能都会中止动作。**腾空 latch 不会中止上台阶**，因为收腿越过台沿时轮子天然会短暂离地；轮输出仍按原有安全门控关闭，落地后恢复。总超时为 `stair_timeout_ms`，再次触发冷却为 `stair_cooldown_ms`。
- `stair_preimpact_diff_max` 是预武装的低加速度门控，`0` 表示关闭。首轮实测表明原始轮速差分在 450 Hz 下量化尖峰很大，`0.6 m/s²` 会让预武装几乎永远攒不满；关闭后由已经确认的高速轮速窗口负责预武装。
- 所有 `stair_*` 参数都可通过 RTT / 调参网页实时修改；VOFA 字段 157..173 提供状态、触发进度、轮速特征、左右腿撞击标志和速度/预武装/撞击确认计时。字段 174..176 追加 `rc_source`、`remote_s1`、`remote_s2`，用于区分 S1 主动急停、遥控源切换和帧超时。

## 自动下平台（空中伸腿与落地缓冲）

- 仅在 **S2 最高档** 且已经处于长腿站立，或刚刚完成自动上台阶、仍保持短腿锁定时启用。普通中低档不会触发。
- 离台检测优先使用整机离地候选的短确认窗口 `descent_start_confirm_ms`（默认 `40 ms`），不必等待普通离地 latch 的 `100 ms` 确认。没有上台阶锁定时还要求实际行驶速度超过 `descent_start_speed`，避免把人工抬起误判为下平台。
- `EXTEND` 阶段目标腿长以 `descent_extend_rate`（默认 `0.35 m/s`）斜坡伸向 `descent_extend_length`。如果离台前腿长已经高于该值，则至少再伸长 `20 mm`，并受机械上限约束。空中使用独立的 `descent_kp_length`、`descent_kd_length`、`descent_max_force` 和 `descent_support_force`，默认支撑前馈为 `0`，避免伸腿动作本身被误当成触地负载。
- 平均绝对关节力矩超过 `descent_contact_torque` 并保持 `descent_contact_confirm_ms`（默认 `20 ms`）后确认触地。进入 `CUSHION` 的同一控制周期立即恢复轮平衡输出，不再等待普通离地检测的 `500 ms` 释放滞回。
- `CUSHION` 阶段以 `descent_return_rate`（默认 `0.60 m/s`）把双腿目标收回到离台前实测腿长，吸收落地冲击；收回完成或到达 `descent_cushion_timeout_ms` 后结束。空中超时则中止，由普通离地检测重新接管轮输出安全门控。
- `descent_*` 参数均可通过 RTT / 调参网页实时修改。VOFA 字段 177..186 记录下降阶段、中止原因、触地标志、离台长度、空中目标、斜坡目标、触地力矩、触地耗时和触发/中止计数。

## 跟随接地伸长（可选）

默认**关闭**，可在调参网页「跟随接地伸长」分组实时开关与调参。

开启后：某条腿一旦**不承重**（复用离地检测的单侧 latch），它的腿长目标就以
`leg_follow_rate` 向外跟随，配合原有的支撑前馈把轮子重新压回地面；直到目标到达
**0.385 m 行程上限**才停止伸长。到顶之后再抬升，轮子才真正离地，此时由离地检测接管。
该腿重新承重后，额外的伸长量以 `leg_follow_return_rate` 回到档位值，避免每次抬升都把
站立高度往上棘轮。

关闭该功能时，腿长环保持 S2 档位目标：被抬升会被当成位置偏差，产生回缩力把轮子往机身
方向拉，所以腿在到达行程上限之前就停止跟随。

| 参数 | 默认 | 说明 |
| --- | ---: | --- |
| `leg_follow_enable` | 0 | 使能，默认关闭 |
| `leg_follow_auto_scope` | 1 | 按 roll 方向自动选择触发范围（见下） |
| `leg_follow_machine_wide` | 1 | 固定触发范围，仅在 `auto_scope=0` 时生效 |
| `leg_follow_roll_deadband` | 0.10 rad | 水平死区，约 5.7° |
| `leg_follow_scope_confirm_ms` | 250 ms | 低侧判定需保持多久才被采信 |
| `leg_follow_episode_timeout_ms` | 3000 ms | 脱空事件在无 latch 后的最长存活时间 |
| `leg_follow_rate` | 0.20 m/s | 脱空时目标外伸速率 |
| `leg_follow_return_rate` | 0.05 m/s | 重新承重后回位速率 |

前提：该功能的"脱空"判据来自离地检测的单侧 latch，所以**离地检测必须处于使能状态**
（`airborne_detect_enable = 1`），否则该功能不会动作。

### 伸长哪条腿：永远伸【低侧】

判定依据是**机身朝哪边倾**，不是"哪条腿脱空" —— latch 只是症状。

| 处境 | 低侧 | 伸低侧的效果 |
| --- | --- | --- |
| 一侧掉下平台 | 掉下去那条 | 够到低处的地面 |
| 平地抬起一侧 | 着地那条 | 把机身整体顶起来 |

两种情况**动作相同**，所以不需要"抬起/掉落"分类器 —— 只需要可靠地读出哪边低。这同时让未判定
窗口变得安全：伸低侧不可能把机身撬下平台，最坏情况只是"暂时没伸"。

> **这里换过一次设计。** 上一版按「脱空侧在 roll 的**高**侧 → 被抬起 → 双腿伸长」判定，实测
> 失败：把一侧推下平台时，**平台侧**那条腿会先失去负载（力矩瞬间掉到 1.9 N·m，刚好低于 2.0
> 的置位阈值，持续 120 ms），而它几何上就在高侧。于是"掉落"被读成"被抬起"，两条腿一起伸，
> 把机身继续撬向掉落侧 —— 最终两腿都顶到行程上限、roll 到 38.7°，仍然没有够到任何东西。
>
> `body.roll` 为正表示**右侧偏高**，所以低侧映射为：`roll > +deadband` → 左侧低，
> `roll < -deadband` → 右侧低，死区内 → 读不出。

**单帧不作为证据。** 一次判定必须持续 `leg_follow_scope_confirm_ms`（默认 250 ms）才被采信；
候选一变（包括变成"水平"）计时清零重来。定下后**锁住**，直到本次事件结束 —— 因为本功能自己的
伸腿动作会把机身推过水平位置。

未判定期间只对**既脱空、又处在低侧**的那条腿伸长，构造上不会去推高侧。

`leg_follow_machine_wide`（固定双腿/单腿）现在**只在 `auto_scope=0` 时生效**，保留它是为了能
不改固件做对照实验。

### 事件为何要比 latch 活得久

跟随伸腿会**抬高关节力矩**，而它等待的正是同一个力矩 latch —— 于是形成一个自我拆台的循环：

```
伸腿 → 力矩上升 → 越过释放阈值 → latch 掉 → 伸长量回退 → 力矩下降 → latch 再置位 → 又伸
```

实测这一循环周期约 1 秒：一次只伸出去约 **14 mm** 就释放，然后回退 **102 mm**，反复两次，始终
攒不出足够的伸出量去够到任何东西。

因此**脱空事件的存活时间独立于 latch**：

- 机身还倾着（`|roll| > deadband`）时事件保持，伸长量**保持并继续追**，不回退；
- 机身回到水平后事件结束，伸长量按 `leg_follow_return_rate` 回位；
- `leg_follow_episode_timeout_ms`（默认 3000 ms）是兜底：如果一直不回平（比如机器停在平台边上），
  超时后照样回位，避免无限保持。

判定完成后，**锁定的低侧那条腿在整个事件期间持续追**，即使它的 latch 已经掉线 —— 够地本来
就是目的，而 latch 在腿开始推的时候必然会掉。
