## 1. 一句话结论

**MPC 接管路线被实机证伪；静漂的真正解法在 LQR 侧，已经落地。**

- 三次满权限接管尝试全部发散，最后一次在 0.4 秒内失控；
- 静漂的本质是 5 秒周期、10 cm 量级的**静摩擦极限环**，不是偏置，
  所以积分器永远治不好；
- 有效手段是**速度阻尼调度 + 位置锚点重锚定**：静置峰峰 105 mm → 32 mm，
  被踢后不再强行回原点；
- MPC 代码保留（求解器、模型生成、影子遥测都是资产），但默认全部关闭，
  运行时不占开销。

## 3. 阶段一：MPC 影子路径与性能（11-06）

### `8174209` Add verified stable2 MPC shadow path

- 保留 LQR 作为实际执行控制器，MPC 只计算不输出；
- 增加独立的**轮子权限**与**关节权限**，可逐步混控；
- 增加求解计数、失败计数、饱和计数、原始输出遥测；
- 新增 `App/Src/vmc_mpc.c`（固定尺寸求解器）、`vmc_mpc_model.c`（按腿长
  插值的 A/B 模型表）、`scripts/derive_vmc_lqr_abk.py` 的 MPC 模型生成。

这是整条线的起点：先让 MPC 能安全地"看着跑"，再谈接管。

### `18124d2` Cache MPC Hessian factor and LQR gains

- Hessian 只在腿长变化超过阈值时重建并做 Cholesky 分解；
- 左右轮共用一次分解；
- LQR 增益也缓存。

目的：把 20×20 的分解从每拍一次降到"腿长变了才做"。

### `e63e190` Move LQR hot path to single precision

- LQR 热路径的软件双精度运算迁移到单精度，保留关键状态精度。

实测循环频率：纯 LQR 约 444–450 Hz；单精度 LQR + 影子 MPC 约 325 Hz，
优化后回到 333–366 Hz。

### `e3d69a9` ~ `bc4199b` MPC 稳态误差积分状态

一串六个提交给 MPC 加了第 7 个状态（位置积分误差），并反复调整它的门控：

- `e3d69a9` 增加积分状态 `x_integral(k+1) = x_integral(k) + Ts·x_error(k)`；
- `51478ef` 仅低速时允许积分（速度阈值 0.08 m/s）；
- `bd1b877` 控制器接管瞬间锚定积分；
- `dc90de1` 增加积分门控原因码遥测（0–17，见主题文档 4.3 节）；
- `6265a63` 低速需连续保持 1 秒才允许积分；
- `bc4199b` 降低积分增益（0.05）并把限幅收到 ±0.02。

结果：积分饱和比例从约 90% 降到 38%，但**位置慢周期没有消失**。
这是后来"静漂是极限环不是偏置"这一结论的第一条线索。

### `cb3b0cb` Fix capture progress without a full window

采集工具的进度显示修复，与控制器无关。

## 4. 阶段二：真正的增量 MPC（11-07 ~ 11-08）

### `0999e0f` Smooth MPC handoff and gate integral motion

- 权限爬升期间冻结积分；
- 平滑交接。

### `f0c1ca4` Use true incremental MPC control variables

改造前其实是"增广积分状态 + 绝对控制量 + 速率惩罚"的 MPC，名称并不准确。
这个提交换成真正的增量形式：

- 决策变量是 `Δu`；
- 绝对量由 `u(k) = u_prev + ΣΔu` 累积；
- `G` 表示预测状态对 `Δu` 的累积影响；
- 阶段代价只惩罚 `Δu`；
- 绝对力矩约束通过增量序列投影保证（单步轮 0.20 N·m、关节 2.0 N·m）；
- 热启动改为增量序列。

模型表 `vmc_mpc_model.c` 全部重新生成。求解耗时从约 870 µs 升到约 1102 µs。

## 5. 阶段三：影子同步与首次实机（11-09）

### `fe71d0b` Fix MPC handoff feedback, align sample time, add runtime delta weights

这个提交同时修了三件事，也记录了两起实机事故：

**（1）权限爬升期把混控输出同步回 `u_prev`，构成正反馈**

```text
u(k) = (1 - a)·LQR + a·u(k-1) + a·Δu(k)
```

极点落在 `z = a`，`Δu` 到输出的增益是 `a/(1-a)`：0.5 时 1 倍、0.9 时 9 倍。
实机在权限爬到 0.8–0.9 时发散，轮电流打满 15000、位移 60 cm、需要急停。

修复：同步只在**纯影子**模式生效（`mpc_apply_requested == 0`）。

**（2）混控基准改"上一拍下发量"导致腿指令冻结**

中间尝试过把混控基准从 LQR 改成实际下发量，结果在腿权限为 0 时公式退化成
`u(k) = u(k-1)`——腿指令被冻结、持续顶机身，机器人被顶离地。已回退，
并加测试锁死"零权限时输出必须等于 LQR 指令"。

**（3）采样周期与模型差 31%**

```text
VMC_CONTROL_PERIOD_US      = 2222   （设计 450 Hz）
vmc_mpc_model_sample_time_s = 0.002222
实测 loop_dt                = 2915 µs ≈ 343 Hz
```

LQR 和卡尔曼都用实测 dt，只有 MPC 的模型表无法吸收。修复：周期改为
3000 µs（333 Hz），模型按 0.003 s 重新生成，并加测试交叉校验两者。

**（4）Δu 权重降到 0.25，并做成运行时参数**

主机试验台扫参（模型对自己，偏乐观）：

| Δu 权重 | 位置尾摆 | 速率饱和 | Δu RMS |
|---:|---:|---:|---:|
| 10.0 | 32.6 mm | 0.0% | 0.027 |
| 4.0 | 26.2 mm | 1.2% | 0.034 |
| 1.0（原） | 20.1 mm | 2.4% | 0.039 |
| 0.25（采用） | 13.9 mm | 7.3% | 0.064 |
| 0.05 | 12.6 mm | 15.8% | 0.094 |

反直觉但成立：加大速率惩罚会让位置摆得更大，因为漂移是静摩擦极限环，
力矩变化越平缓，系统越容易长时间卡在静摩擦区。

## 6. 阶段四：放弃 MPC 接管，转 LQR（11-11 ~ 11-12）

转折点是 0.5 权限实验：MPC 速率限幅饱和 **99%**、轮电流 ±6500、
7 Hz 极限环；换成正确的 3 ms 模型后毫无改善；**一断开 MPC 立刻恢复**。
结论：增量 MPC 在部分权限混控下没有自洽解。

### `12364c8` Add wheel odometry baseline and MPC absolute-input cost

**（1）轮速里程计成为真值**

右电机镜像安装，两条原始轮速通道反相（相关系数 −0.95 ~ −0.99），
机体速度是差值的**一半**：

```text
v_body = (right_raw - left_raw) / 2
```

手推 20 cm 四次，原始读数 345–385 mm，乘 0.5 后为
**172.8 / 175.8 / 186.7 / 192.6 mm**；左右轮差值只有速度 RMS 的 11%，
与 `kf_dx` 相关性 0.993。结论：尺度 0.5，低速不打滑成立。

顺带发现固件 `motion.wheel_dx` 也差 2 倍（未除 2），它只被台阶检测当速度
阈值用，意味着台阶触发门槛只有设定值的一半——已记录，未改。

**（2）静漂基线（这是最重要的测量）**

纯 LQR、62.6 秒稳定段：

| 指标 | 数值 |
|---|---:|
| 净漂移 | −6.3 mm（−6.0 mm/min） |
| 峰峰值 | **105.3 mm** |
| 慢周期 | **5.0 s** |
| `kf_dx` RMS | 0.0395 m/s |
| 轮电流 RMS / 峰值 | 490 / 1419 |

**净漂移极小但峰峰 10.5 cm**：这是极限环，不是偏置。积分器只能消偏置，
治不了极限环——这解释了历史上所有积分/死区试验为什么会失败。

**（3）补绝对控制量代价**

增量代价只惩罚 `Δu`，稳态力矩"免费"，求解器因此长期顶在速率限幅上
（实机 93–99% 饱和）。加入 `J += Σ u_kᵀR_u u_k`：

- Hessian 加重叠矩阵 `A[m][n] = (H − max(m,n))·R_u`；
- 线性项加 `A·u_prev`；
- 权重做成运行时参数 `mpc_abs_weight_wheel/leg`。

主机扫参：`R_u = 0.1` + 限幅 1.0 时位置不变（13.5 mm）、饱和从 7.3% 降到
1.6%；`R_u ≥ 1.0` 位置尾摆翻倍。**默认值保持 0/0.2**，因为主机模型量不出
真实静摩擦。

### `5274154` Add dwell-activated velocity damping for the standing limit cycle

同一次采集内切换增益（避开跨运行差异，两次纯 LQR 基线峰峰就能差 1.75 倍）：

| `dx_feedback_gain` | 峰峰值 | `kf_dx` RMS | 电流 RMS / 峰值 |
|---:|---:|---:|---:|
| −0.5 | **693.0 mm** | 0.268 | 1269 / 4819 |
| −1.0（原默认） | 56.5 mm | 0.0263 | 384 / 1266 |
| −1.5 | 54.1 mm | 0.0202 | 470 / 1274 |
| −2.0 | **37.4 mm** | 0.0143 | 476 / 1125 |

−0.5 直接失控（走 39 cm），说明默认 −1.0 就踩在稳定边界附近。

实现**驻留强阻尼**：摇杆松开、无特殊流程、低速，持续 1 秒后从 −1.0 升到
−2.0；任一条件不满足立即回落（加 4/s、撤 20/s，不对称）。

三道门控各自对应一次真实故障：

1. **特殊流程**：自起全程摇杆是松开的，早期版本自起 1 秒后就被套上 −2.0；
2. **速度**：被踢时摇杆同样松开，−2.0 在大信号下会变成正反馈；
3. **使能隔离**：使能瞬间 `vmc_dx_gain_applied` 保留断开前的 −2.0，
   而腿正在按 0.225 m/s 的斜坡伸出——现在使能后 3 秒内强制 −1.0 且直接赋值。

实机：干净稳态段 **22.3 mm**（对照 −1.0 的 56.5 mm），四次踢击全部恢复、
未发散，踢击期间实际增益为 −1.0（由 `dx_error/kf_dx` 反推确认）。

### `208242c` Debounce the jump switch, schedule the standing gain, drop stale buffers

**（1）跳跃开关 300 ms 去抖（安全问题）**

现象：跳跃档位明明是关闭的，机器人突然起跳；其中一次冲击把电池震脱。

根因两条叠加：

- 手动跳跃**一帧就触发**，没有确认窗口；
- SBUS 25 字节帧没有校验和，只校验帧头/帧尾，载荷任何一位翻转都会进入通道值；
- 而且开关档位映射是"中间 = 自动跳跃"，拨动时必然经过中位。

修复：选中的模式必须**稳定保持 300 ms** 才能让手动或自动任何一条路径上膛。

**（2）速度门控改成连续调度**

硬门控在 `|dx| > 0.10` 时锁死 −1.0，而踢后残留震荡正好落在 0.1–0.2 m/s，
衰减极慢（6–10 秒）。改为：

```text
|dx| ≤ 下拐点            → 全强阻尼
下拐点 < |dx| < 上拐点   → 线性插值
|dx| ≥ 上拐点            → 正常增益
```

两个拐点都是运行时参数（默认 0.10 / 0.20）。

**（3）安全检查丢弃陈旧缓存**

J-Link 会先吐出上一次会话的缓冲，安全检查因此误报"遥控离线但输出仍活动"，
阻止了合法烧录。现在按时间戳跳变丢弃缓存段并报告丢弃帧数。

### `ed0e1ae` Re-anchor on a disturbance instead of walking back

`x_hold_max_stretch` 既是"回拉前允许的拉伸量"，也是"控制器最多会把机器人
走回多远"。默认 0.25 m 时，踢远之后控制器会主动走回原点（实测 `x_error`
从未超过 0.197，说明锚点根本没拖，全程都在回拉）。

操作员要的是"在被踢落的位置保持平衡"，默认改为 **0.06 m**：位移超过 6 cm
锚点跟随，就地停下；6 cm 以内的慢漂移仍照常纠正。

## 10. 遗留问题

1. **硬踢后的残留极限环**（55–103 mm）回不到 22 mm。这是静摩擦滞回，
   改增益解决不了，需要摩擦前馈或独立的恢复策略。
2. **`motion.wheel_dx` 差 2 倍**，台阶检测的速度门槛因此只有设定值的一半。
3. **观测器是"静态配平学习器"**，不是 LESO：只有一个标量扰动、只在摇杆
   松开且低速时工作，无法补偿坡道上的持续扰动。参考
   `开源参考/Qi-Q26-Leg_Robot 2`（山东理工）用的是 6 状态 LQR + 8 状态 LESO
   （轮/腿各一个扰动状态），可按腿长调度，是上斜坡更对的方向。
4. **环频只有 333 Hz**：控制周期被 MPC 求解（约 1.1 ms）钉到 3 ms。MPC 关闭
   后循环体约 1.8 ms，理论上可回到 450 Hz，单拍延迟减少 0.8 ms，可能直接
   改善相位裕度和残留极限环。这是一次需要重新验证 KF/起立/阻尼的改动。
5. **安全检查工具**已修缓存问题，但 `busy` 统计仍覆盖整个窗口，建议后续
   按实时段统计。
