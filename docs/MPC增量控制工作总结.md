## 1. 文档目的

本文记录本次 aboard 平衡控制器的 MPC 改造、性能优化、积分器设计、实机测试、
回退处理、遥测修复和后续计划。

2. 已烧录并完成实机验证的代码。

## 2. 当前结论

- 原控制器已经具备 MPC 影子计算和权限混控能力。
- MPC 状态已扩展为 7 维，包含位置积分误差状态。
- 当前代码已从“绝对控制量 MPC + 控制增量惩罚”切换为真正的增量 MPC。
- 真正的增量 MPC 以 `Δu` 为优化变量，预测中的绝对控制量由
  `u(k) = u_prev + ΣΔu` 累积得到。
- 位置积分状态继续保留，用于抑制静止位置偏差。
- 轮子 MPC 已能稳定完成影子计算，但影子输出与 LQR 仍存在较大偏差。
- 最新修复让影子计算和权限过渡阶段的 `u_prev` 同步为机器人实际执行的
  受限控制量。该修复已通过主机构建与测试，尚未烧录。
- 关节 MPC 尚不应启用。轮子 MPC 的低速漂移和慢周期问题仍未彻底解决。

> 第 14 节推翻或修正了本节的三条旧结论：影子同步已缩小到纯影子模式；
> 权限爬升期的 `u_prev` 同步是事故一的根因；"权限逐步爬到 1.0 做 A/B"
> 的协议不成立，因为增量 MPC 在部分权限下没有自洽解。阅读时以第 14 节为准。

## 3. 初始问题与背景

原始需求包括：

- 从 `stable2` 建立 MPC 分支。
- 解决实机静止站立时前后漂移。
- 轮地摩擦较大，轮速与机身位移存在明显滑移和静摩擦。
- 原方案没有把轮速与 IMU 位置观测做充分融合。
- 希望评估增量 MPC 能否减少模型失配下的持续控制偏置。
- MPC 计算必须适配 STM32F427 的实时控制周期。

早期 `stable2` 还存在起立问题。为了区分起立故障和 MPC 改动，原始控制内容
局部回退到提交 `28777b3`，MPC 新增内容保留。

## 4. 主要工作阶段

### 4.1 建立可验证的 MPC 影子路径

关键提交：

- `8174209 Add verified stable2 MPC shadow path`

工作内容：

### 4.2 MPC 性能优化

关键提交：

- `18124d2 Cache MPC Hessian and LQR gains`
- `e63e190 Move LQR hot path to single precision`

工作内容：

- 按 9 个腿长工作点离线生成 MPC 模型。
- `G` 和 `H` 存入 Flash 模型表。
- 运行时对腿长对应模型进行插值。
- Hessian 仅在腿长变化超过阈值时重建和分解。
- 左右轮共用一次 Hessian 分解。
- LQR 热路径中的软件双精度运算迁移到单精度。
- 保留关键状态估计和控制状态的必要精度。

历史频率参考：

- 纯 LQR：约 444 至 450 Hz。
- 单精度 LQR 加影子 MPC：约 325 Hz。
- 后续优化和增量 MPC 阶段：约 333 至 366 Hz。

### 4.3 增加 MPC 稳态误差积分状态

关键提交：

- `e3d69a9 Add MPC steady-state error integrator`
- `51478ef Gate MPC integral state by low-speed stability`
- `bd1b877 Anchor MPC integral at controller handoff`
- `dc90de1 Add MPC integral gate diagnostics`
- `6265a63 Require sustained low speed for MPC integral`
- `bc4199b Reduce MPC integral gain and clamp`
- `0999e0f Smooth MPC handoff and gate integral motion`

最终状态为：

```text
[theta, dtheta, x, dx, phi, dphi, x_integral]
```

模型中的积分状态：

```text
x_integral(k+1) = x_integral(k) + Ts * x_error(k)
```

运行时特性：

- 积分权重初始为 `0.05`。
- 积分限幅为 `±0.02 m·s`。
- 仅低速时允许积分。
- 速度阈值 `0.08 m/s`。
- 低速连续保持 1 秒后才允许积分。
- 位置误差超过 `0.25 m` 时清零。
- 权限爬升期间冻结积分。
- 返回锚点时快速泄放积分。
- `±0.01 m` 位置死区。
- 退出速度控制、起立、上台阶、跳跃、腾空、反馈超时和倒地复位时清零。

积分诊断原因：

| 原因码 | 含义 |
|---:|---|
| 0 | 正常积分 |
| 1 | 摇杆速度控制 |
| 2 | 速度控制释放 |
| 3 | 手动预摆位 |
| 4 | 起立流程 |
| 5 | 上台阶流程 |
| 6 | 跳跃流程 |
| 7 | 腾空 |
| 8 | 反馈超时 |
| 9 | 倒地复位 |
| 10 | 速度过高 |
| 11 | 位置误差超限 |
| 12 | MPC 未计算 |
| 13 | 求解失败 |
| 14 | 低速驻留不足 1 秒 |
| 15 | MPC 权限爬升中 |
| 16 | 正在返回锚点 |
| 17 | 位置死区 |

### 4.4 修正 MPC 权限爬升与观测器交接

发现的问题：

- 原代码只要 `mpc_enable=1` 就立即关闭扰动观测器。
- 此时 MPC 轮子权限仍接近 0，LQR 实际仍在输出。
- 结果是 LQR 的观测器补偿被提前移除，接管阶段产生明显漂移。

修复：

- MPC 权限从 0 爬升到 100% 时，扰动观测器继续工作。
- 只有轮子 MPC 权限达到 100% 后才关闭观测器。
- LQR 观测器补偿随权限混控自然淡出。
- 权限爬升期间位置积分保持冻结。

修复前后的接管位移：

| 测试 | 接管时间 | 接管位移 |
|---|---:|---:|
| 修复前正向 A/B | 4.99 s | 约 +12.4 cm |
| 修复后正向 A/B | 4.96 s | 约 -0.9 cm |
| 修复后反向 A/B | 4.97 s | 约 -1.7 cm |

该修复显著降低了权限交接瞬态。

### 4.5 三态积分门控

后续测试发现积分会在机器人已经返回锚点时继续饱和，造成慢周期超调。

新增逻辑：

```text
|x_error| > 1 cm 且 x_error * dx_error > 0：远离锚点，允许积分
x_error * dx_error < 0：返回锚点，冻结并快速泄放
|x_error| <= 1 cm：位置死区，冻结并泄放
```

快速泄放系数：

```c
#define VMC_MPC_X_INTEGRAL_FAST_DECAY 0.99f
```

在约 366 Hz 下，积分约 70 个控制周期衰减一半，约 0.19 秒。

三态门控后的效果：

- 积分饱和比例从约 90% 降低到约 38%。
- 返回锚点原因码 16 能正常出现。
- 位置慢周期仍未完全消失。

### 4.6 3 cm 死区试验与回退

曾将位置死区从 1 cm 调整为 3 cm。

结果：

- 真正回程时最小位置误差仍约 5.9 cm。
- 3 cm 死区没有覆盖主回程。
- 原因码 17 没有在有效回程中触发。
- 积分饱和比例下降到约 24.5%，但最大位置偏移反而增大。
- 该试验无法证明 3 cm 死区有效。

最终已将死区恢复为：

```c
#define VMC_MPC_X_INTEGRAL_POSITION_DEADBAND 0.01f
```

### 4.7 从“类增量”MPC 切换为真正的增量 MPC

改造前实际结构：

- 7 维增广状态。
- 优化变量仍是绝对力矩 `u`。
- 目标函数中存在 `(u - u_prev)` 型惩罚。
- 有速率限幅，但预测模型中没有 `Δu` 累积。

因此改造前更准确的名称是：

```text
增广积分状态、绝对控制量、带速率惩罚的 MPC
```

真正增量 MPC 改造：

```text
决策变量：Δu(k)
绝对控制量：u(k) = u_prev + Σ Δu(j), j <= k
```

具体代码变化：

- `G` 表示预测状态对 `Δu` 的累积影响。
- 基准预测包含保持 `u_prev` 的未来状态。
- 阶段目标函数仅惩罚 `Δu`，不再惩罚绝对 `u`。
- 绝对力矩约束仍通过增量序列累积投影保证。
- 单步轮子增量限制为 `0.20 N·m`。
- 单步关节增量限制为 `2.0 N·m`。
- 规划热启动改为增量序列。
- 周期切换时规划左移，并将最后一步增量置零。
- 规划遥测输出由增量重建后的绝对力矩轨迹。

关键提交：

- `f0c1ca4 Use true incremental MPC control variables`

离线模型已重新生成：

```text
App/Src/vmc_mpc_model.c
```

- 右轮规划最大相邻步进严格为 `0.200 N·m`。
- 实际 `wheel_delta` 未超过限制。

该修复尚未提交。

### 4.9 影子模式下的 `u_prev` 同步

发现问题：

- 真增量 MPC 在影子模式下继续进行假想规划。
- 机器人实际执行的仍然是 LQR。
- 原先 `u_prev` 只在 MPC 完全空闲时从 LQR 初始化一次。
- 影子 MPC 随后沿自己的假想输入演化，预测基准逐渐偏离实际系统。

实测偏差：

- LQR 左右轮力矩 RMS 约 `0.16 N·m`。
- MPC 影子左右轮力矩 RMS 约 `0.90 N·m`。
- 影子和 LQR 最大差约 `1.78 N·m`。
- 直接全权限接管会产生明显冲击。

当前已修改但尚未烧录：

- 新增 `vmc_mpc_sync_previous_input()`。
- 纯影子模式下，每拍将 `u_prev` 同步为上一周期最终受限的实际输出。
- MPC 权限过渡期间也同步实际混控输出。
- 同步时清空旧增量计划。
- 权限稳定达到目标后停止同步，让增量 MPC 闭环自行递推。

该修改已通过：

- 定向 C 求解器测试。
- 全部 338 项测试。
- Debug 编译。
- Release 编译。

## 6. 已完成的实机测试

### 6.1 影子性能

较早的稳定影子测试：

- 求解中位数约 `870 µs`。
- P95 约 `887 µs`。
- 最大约 `900 µs`。
- 无求解失败。

### 6.2 轮子权限 A/B

已验证：

- LQR 与 MPC 权限可独立混控。
- 轮子权限爬升期间关节 MPC 权限保持 0。

## 7. 关键失败与经验

### 7.1 不能只看主机时间戳

RTT 可能先返回旧缓存，主机时间与固件时间不一致。

后续分析必须：

- 使用 `mcu_time_ms`。
- 按 `control_enabled`、`mpc_enable`、`mpc_active` 和权限切换点分段。
- 将每次采集前 10 秒排除。

### 7.2 积分器不是漂移的唯一原因

同一慢周期在 MPC 和 LQR 恢复段都存在，说明还存在：

- 轮地静摩擦。
- 滑移。
- 位置估计偏差。
- 位置环欠阻尼。
- 机械静态偏置。

继续只调积分死区或限幅无法根治。

### 7.3 影子模式必须使用真实上一拍输入

增量 MPC 的 `u_prev` 必须是机器人实际施加的控制量。

影子模式下如果让 MPC 沿自己的假想输入递推，影子输出会逐渐偏离 LQR，导致：

- 影子测试失去参考意义。
- 接管前状态不一致。
- 权限混控产生冲击。

### 7.4 所有规划量都要有明确语义

必须明确区分：

- 绝对控制量 `u`
- 控制增量 `Δu`
- 原始 QP 输出
- 限幅后的实际输出
- 增量重建后的绝对规划

遥测字段命名和索引必须与固件发送顺序严格一致。

## 9. 后续计划

### 第一步：烧录并验证真实输入同步

前置条件：

1. 机器人支撑或悬挂。
2. 遥控通道 4 上拨到 STOP，或关闭遥控。
3. 执行安全检查：

```sh
cd aboard
python3 tools/check_safe_to_flash.py
```

4. 仅在返回码为 0 时烧录 Release。

### 第二步：纯影子验证

运行时参数：

```json
{
  "type": "vmc_balance_params",
  "mpc_enable": 0,
  "mpc_shadow_enable": 1,
  "mpc_wheel_authority": 0.0,
  "mpc_leg_authority": 0.0
}
```

至少采集 30 秒，并保持控制器使能。

验收条件：

- `mpc_solve_us > 0`
- 求解失败计数不增加
- 左右规划相邻步进不超过 `0.20 N·m`
- MPC 影子与 LQR 轮子力矩 RMS 差小于约 `0.2 N·m`
- 最大瞬时差小于约 `0.5 N·m`
- 控制频率不低于约 `330 Hz`

### 第三步：轮子权限爬升 A/B

建议顺序：

```text
0 至 10 秒：缓冲与起立，丢弃
10 至 20 秒：LQR 基线
20 至 40 秒：MPC 轮子权限逐步到 1.0，关节权限保持 0
40 至 50 秒：关闭 MPC，恢复 LQR
```

建议权限爬升率：

```text
0.2 /s
```

需要比较：

- `kf_x` 净漂移。
- `kf_x` 峰峰值。
- `kf_dx` 均值和 RMS。
- 轮电流峰值。
- Pitch RMS。
- 积分饱和比例。
- 原因码 15、16、17 的持续时间。
- MPC 与 LQR 的力矩差。
- 控制频率和求解 P95。

### 第四步：性能优化

当前增量 MPC 求解中位数约 `1102 µs`，控制频率约 `333.6 Hz`。

在行为验证通过后，可评估：

- 降低不必要的 ADMM 迭代。
- 改善 Hessian 条件数。
- 减少每拍的基准预测重复计算。
- 检查 Flash 等待和 Cache 对 20×20 模型数据读取的影响。
- 将部分不随腿长变化的量缓存在 CCMRAM。

不得在行为和稳定性未确认前只追求频率。

### 第五步：轮子稳态测试

只有在影子输出与 LQR 接近后，才允许做：

- 长时间静止漂移测试。
- 轮子权限多次 A/B。
- 正反顺序重复测试。
- 外部实际位移测量对照。

### 第六步：关节 MPC

关节 MPC 最后启用。

开启前必须满足：

- 轮子 MPC 长时间稳定。
- 权限过渡无冲击。
- 积分无持续饱和。
- 关节输出方向和限幅验证完成。

### 14.1 影子复测

烧录"影子期同步 `u_prev` + 规划遥测索引修复"后，悬空、CH4 使能、权限 0，
采集 45 s：

| 指标 | 结果 |
|---|---:|
| 求解 中位 / P95 / 最大 | 1108 / 1125 / 1146 µs |
| 求解失败 | 0 |
| `loop_dt_us` 中位 | 2915 µs ≈ 343 Hz |
| 轮子影子 vs LQR 力矩 RMS 差 | 0.187 N·m（上一版 0.90） |
| 最大瞬时差 | 0.264 N·m |

同步修复确实生效，影子输出已经贴住 LQR。但有两个要注意的地方：

1. 影子模式下每拍把 `u_prev` 重置为实际输出，而单步增量上限是 0.20 N·m，
   所以 `|MPC − LQR| ≤ 0.2` 是结构上保证的。这个指标不再能证明 MPC 的

2. 规划遥测退化：`finalize_output()` 用 `initial_plan`（ADMM 热启动增量）重建

   `u_prev`，相邻步进恒为 0。第 9 节"规划相邻步进 ≤ 0.20 N·m"的验收项
   在此期间是空过的。修法是改用解出来的 `axis->plan` 重建，尚未实施。

### 14.2 事故一：权限爬升到 0.8–0.9 时发散

时序：`0–10 s` LQR 基线，`10 s` 开 MPC，权限按 0.2/s 爬升，`40 s` 回 LQR。

| 阶段 | `kf_x` 范围 | `kf_dx` RMS | 轮电流 RMS / 峰值 | pitch |
|---|---:|---:|---:|---:|
| LQR 基线 | +4.8 ~ +13.2 cm | 0.033 | 506 / 1735 | ±0.02 |
| 权限爬升 | +6.0 ~ +27.5 cm | 0.428 | 5320 / 15000（饱和） | ±0.13 |
| 满权限/急停 | 0 ~ 65.9 cm | 2.007 | 10040 / 15000 | ±0.31 |

`mpc_failure_count=0`、`saturation_count=0`，求解本身没有报错，是闭环发散。

根因：爬升期代码每拍执行

```c
vmc_mpc_sync_previous_input(0, vmc_balance.left_wheel_torque_limited, ...);
```

而它是**上一拍混控后**的输出，于是

```text
u(k) = (1 - a) * LQR(k) + a * u(k - 1) + a * delta_u(k)
```

齐次部分极点落在 `z = a`，`delta_u` 到输出的稳态增益是 `a / (1 - a)`：
a=0.5 时 1 倍，a=0.9 时 9 倍，a=0.99 时 99 倍。再叠加一拍额外延迟在
170 Hz 的 180° 相移，就形成数据里"每个采样翻一次符号"的交替振荡。

修复：同步只在纯影子模式（`mpc_apply_requested == 0`）生效，混控期让 MPC
沿自己的 `u_prev` 递推。新增源码级回归测试，锁死"同步条件里不得出现权限
比较"。

### 14.3 事故二：混控基准改动把腿指令冻住

为消除"MPC 以为自己的命令被执行、实际只执行一半"的不一致，曾把混控基准
从 LQR 指令改为**上一拍实际下发量**：

```c
left_tp_raw = (1 - leg_authority) * vmc_balance.left_tp_cmd + ...
```

腿权限在轮子测试里恒为 0，于是公式退化成 `u(k) = u(k-1)`——**腿指令被冻结**，
不再跟随 LQR。腿力矩停在原来的值继续推机身，机器人被顶离地面，固件随后检测
到"两侧离地"把轮输出门控掉。轮子通道同理，在低权限时把轮指令变成极点 0.96
的低通，带宽只剩十几 Hz。

已回退，并新增测试：混控块必须出现 `(1.0f - wheel_authority) * left_wheel_lqr`
这类项，**不允许**出现 `*_torque_limited` / `*_tp_cmd`。

教训：这个公式只在权限为 1 时自洽；权限为 0 时它的语义是"保持上一拍"，
不是"等于 LQR"。

### 14.4 采样周期与 MPC 模型对齐

发现模型与真实控制环差 31%：

```text
VMC_CONTROL_PERIOD_US      = 2222   （设计 450 Hz）
vmc_mpc_model_sample_time_s = 0.002222
实测 loop_count / mcu_time  = 333.4 Hz，loop_dt_us 中位 2915 µs
```

LQR 不受影响（静态增益，速率项用实测 dt），Kalman 也不受影响（用实测 dt），
只有 MPC 的模型表无法吸收实测 dt。

修复：

- `VMC_CONTROL_PERIOD_US` 改为 3000（333 Hz），注释同步说明必须与模型一致；
- `vmc_mpc_model.c` 用 `--mpc-dt 0.003` 重新生成；
- 新增测试，直接比对头文件周期与模型采样时间。

烧录后实测 `loop_dt_us` 中位 3000.0、P95 3000、最大 3005，`loop_count` 反算
333.33 Hz，与模型完全一致。

### 14.5 阴性结论：部分权限不是有效工作模式

在 0.5 权限下保持 12 s（3.0 ms 模型）：

| 阶段 | 轮电流 RMS | `kf_dx` RMS | `kf_x` RMS | 速率限幅饱和 |
|---|---:|---:|---:|---:|
| LQR 基线 | 717 | 0.066 | 0.165 | — |
| MPC a=0.5 | 4846 | 0.240 | 0.291 | 99.0% |
| 断开 MPC 后 | 683 | 0.018 | 0.279 | — |

机体以约 7 Hz、±0.33 m/s 来回抖，位置反而略稳。**断开 MPC 的瞬间电流从
±6500 掉回 ±800**，抖振完全由 MPC 驱动。

换成正确对齐的 3.0 ms 模型后，抖振**没有任何改善**（电流仍 ±6500、饱和
99%），所以采样周期不是抖振原因。

结构原因：增量 MPC 的 `u_prev` 是它自己上一条命令，而真正到电机的是
`(1-a)·LQR + a·u_mpc`。两者持续对不上，MPC 一直在追一个不存在的输入，
每个周期都把 0.2 N·m 顶满，退化成 bang-bang。

**因此第 9 节"权限逐步爬到 1.0 做 A/B"的协议对这个控制器不成立**：部分权限
没有自洽解。要么纯影子，要么满权限硬切换。

### 14.6 Δu 权重扫参（主机试验台）

给 `tools/test_vmc_mpc.c` 的闭环测试加了三个指标：位置尾摆、速率限幅饱和率、
Δu RMS。用真实模型 + 真实求解器 + 3 ms 周期扫 `MPC_DELTA_WEIGHT`：

| Δu 权重 | 位置尾摆 | 速率饱和 | Δu RMS | 轮力矩 RMS |
|---|---:|---:|---:|---:|
| 10.0 | 32.6 mm | 0.0% | 0.027 | 0.371 |
| 4.0 | 26.2 mm | 1.2% | 0.034 | 0.388 |
| 2.0 | 21.8 mm | 1.8% | 0.036 | 0.384 |
| 1.0（原） | 20.1 mm | 2.4% | 0.039 | 0.397 |
| 0.25（采用） | 13.9 mm | 7.3% | 0.064 | 0.384 |
| 0.05 | 12.6 mm | 15.8% | 0.094 | 0.387 |

加大速率惩罚反而让位置摆得更大：漂移是静摩擦极限环，力矩变化越平缓，系统

同时把权重做成运行时参数：模型文件输出默认值
`vmc_mpc_delta_weight_default[]`，固件以"相对默认值的偏移"存权重，只改
Hessian 对角项，改动时失效因子缓存。运行时参数名
`mpc_delta_weight_wheel` / `mpc_delta_weight_leg`，扫参无需重烧。

### 14.7 关键发现：实机上 MPC 几乎全程顶在速率限幅

影子模式下实测 `|mpc_*_wheel_delta|` 均值 0.186、最大 0.200，约 **93%**
的周期顶在 0.20 N·m 上限——而同样的控制器在主机试验台（模型匹配）只有
2.4%。

结论：真实机器人上**速率限幅才是真正的执行器，代价权重没有进入工作区**。
因此 14.6 的权重改动在实机上大概率看不出差别。

真正的杠杆只有两个：

1. 放大 `VMC_MPC_WHEEL_DELTA_MAX_DEFAULT`（当前 0.20），让代价函数真正起作用；
2. 或补上绝对控制量代价 `R_u`，让"想要大修正"本身变贵，从根上离开限幅边界。

两者都尚未实现。

## 15. 2026-11-11 轮速里程计标定、静漂基线与第 1 步

### 15.1 用轮速里程计做真值

低速静置时轮子不打滑，轮速里程计比融合估计更可信，且不会自己漂。新增
`tools/wheel_odometry.py`，只取 `kf_wheel_left_raw` / `kf_wheel_right_raw`，
不碰 IMU、不碰卡尔曼：

```text
v_body = (right_raw - left_raw) / 2
```

右电机镜像安装，两条原始通道反相（实测相关系数 −0.95 ~ −0.99），所以必须用
**差值的一半**；用和会互相抵消。

工具会丢弃 RTT 陈旧缓存段、跳过断流，并输出净漂移、峰峰值、速度 RMS、
左右轮差值（滑移指标）以及与 `kf_dx` 的相关性。

### 15.2 手推标定

机器人落地、腿正常出力、`wheel_output_user_enable = 0`（轮子放开）、
控制器使能，手推 20 cm 四次。原始读数 345–385 mm，乘 0.5 后为
**172.8 / 175.8 / 186.7 / 192.6 mm**，与 20 cm 吻合；左右轮差值只有速度
RMS 的 11%，且 `corr(v_odom, kf_dx) = 0.993`。

结论：**尺度 = 0.5，低速不打滑成立**，轮速里程计可以当真值。

顺带发现固件的 `motion.wheel_dx` 也是未除 2 的原始差值（差 2 倍）。它只被
台阶检测当作速度阈值使用，意味着台阶触发的实际速度门槛只有设定值的一半；
本次未改，记录在此。

### 15.3 静漂基线（纯 LQR，62.6 s 稳定段）

| 指标 | 数值 |
|---|---:|
| 净漂移（里程计） | −6.3 mm（−6.0 mm/min） |
| 峰峰值（里程计） | **105.3 mm** |
| 慢周期 | **5.0 s** |
| `kf_x` 变化 / 峰峰 | +15.0 / 126.0 mm |
| `kf_dx` RMS | 0.0395 m/s |
| pitch RMS | 0.0412 rad |
| 轮速 RMS | 0.0385 m/s |
| 左右轮差值 RMS | 0.0140 m/s（36%） |
| 轮电流 RMS / 峰值 | 490 / 1419 |

关键判断：**净漂移极小（6 mm/min），但峰峰值 10.5 cm、周期 5 s，这是一个
极限环而不是偏置**。积分器只能消偏置，治不了极限环——这解释了历史上加大
积分限幅、调死区都无效。同时里程计与融合估计一致（0.992），说明估计器没有
明显漂移，问题在真实机械运动。

### 15.4 第 1 步：绝对控制量代价与可调速率限幅

增量 MPC 的代价只有 `ΣΔuᵀR_δΔu`，稳态力矩不花钱，求解器因此长期顶在
0.20 N·m 的速率限幅上（实机实测 93–99% 饱和）。本次补上绝对控制量代价：

```text
J += Σ u_kᵀ R_u u_k,   u_k = u_prev + Σ_{j<=k} Δu_j
```

实现方式：`u_kᵀR_uu_k` 展开后是一个与原代价同构的二次型，Hessian 加一个
只依赖预测步数的重叠矩阵（`A[m][n] = (H − max(m,n))·R_u`），线性项加
`A·u_prev`。两者都在因子缓存重建时/每拍线性项里计算，开销可忽略。

同时把 `mpc_wheel_delta_max` / `mpc_leg_delta_max` 改成运行时参数。
新增运行时参数：

```text
mpc_abs_weight_wheel / mpc_abs_weight_leg
mpc_wheel_delta_max  / mpc_leg_delta_max
mpc_delta_weight_wheel / mpc_delta_weight_leg   （上一轮已有）
```

`tools/test_vmc_mpc.c` 增加命令行参数（`--abs-wheel`、`--rate-wheel` 等），
`scripts/mpc_weight_sweep.py` 改为对运行中的二进制扫网格，不用重新生成模型。

主机扫参结果（模型对自己，绝对值偏乐观）：

| R_u | 速率限幅 | 位置尾摆 | 速率饱和 | Δu RMS | 轮力矩 RMS |
|---:|---:|---:|---:|---:|---:|
| 0（原） | 0.20 | 13.9 mm | 7.3% | 0.064 | 0.384 |
| 0.10 | 1.00 | **13.5 mm** | **1.6%** | 0.050 | 0.356 |
| 0.25 | 1.00 | 17.1 mm | 1.2% | 0.044 | 0.335 |
| 1.00 | 0.50 | 36.9 mm | 0.7% | 0.053 | 0.356 |

结论：`R_u = 0.1` + 速率限幅 `1.0` 在主机上位置不变、饱和从 7.3% 降到 1.6%、
力矩 RMS 下降；但 `R_u ≥ 1.0` 会让位置尾摆翻倍，不可取。

**注意**：主机模型的极限环只有约 14 mm，实机实测 105 mm，差 8 倍，说明这个
简化模型无法预测静摩擦导致的慢周期。因此这组参数只能在实机上验证，主机
测试只用于排除不稳定。

默认值保持原样（`R_u = 0`、限幅 0.20），全部改为运行时参数，上机时可现场扫，
不需要重烧。

## 16. 驻留强阻尼（2026-11-12）

静漂基线是 5 s、105 mm 的极限环，不是偏置。转向 LQR 后先试最便宜的杠杆：
速度反馈增益 `dx_feedback_gain`（它通过移动腿的目标角提供阻尼）。

### 16.1 同一次采集内的增益扫参

跨运行比较不可用（两次纯 LQR 基线的峰峰就差 1.75 倍），所以改成一次 290 s
采集内每 70 s 切一档：

| `dx_feedback_gain` | 峰峰值 | `kf_dx` RMS | 电流 RMS / 峰值 | pitch RMS |
|---:|---:|---:|---:|---:|
| −0.5 | **693.0 mm** | 0.268 | 1269 / 4819 | 0.0230 |
| −1.0（原默认） | 56.5 mm | 0.0263 | 384 / 1266 | 0.0140 |
| −1.5 | 54.1 mm | 0.0202 | 470 / 1274 | 0.0101 |
| −2.0 | **37.4 mm** | 0.0143 | 476 / 1125 | 0.0098 |

−0.5 会直接失控（机体走了 39 cm），说明默认 −1.0 就踩在稳定边界附近。
−1.0 到 −2.0 单调改善，且电流峰值下降——不是靠更暴力的输出换来的。

### 16.2 驻留强阻尼

强阻尼会让操控变迟钝，所以只在驻留时启用：

- 摇杆松开、且无特殊流程、且 `|kf_dx| <= dx_static_speed_limit`（默认 0.10）
  连续保持 `dx_static_delay_ms`（默认 1000）后，增益从 `dx_feedback_gain`
  升到 `dx_feedback_gain_static`（默认 −2.0）；
- 任一条件不满足立即回落，**释放速率 20/s、投入速率 4/s**（不对称：
  加阻尼慢、撤阻尼快）。

三个必须的门控，缺一个都会出问题：

1. **特殊流程**：自起、跳跃、上台阶、手动预摆位、腾空、反馈超时。自起全程
   摇杆是松开的，早期版本漏了这个门控，自起 1 秒后就被套上 −2.0，干扰起立。
2. **速度门控**：被踢时摇杆同样是松开的。−2.0 只在小信号下稳定（静置
   `|kf_dx|` P99 = 0.031 m/s），大信号（0.3 m/s 以上）下这条腿目标路径会变成
   正反馈。速度超过 0.10 m/s 立刻退回 −1.0。
3. 速度阈值取 0.10 的依据：−2.0 稳态 3190 个样本里 `|kf_dx|` 最大 0.044，
   没有一帧越界，正常静置不会误触发。

### 16.3 实机结果

- 干净稳态段（第一次踢之前 13 s）：**22.3 mm**，对照 −1.0 的 56.5 mm，
  改善约 60%。
- 四次踢击（峰值 0.57–1.43 m/s）：**全部恢复，不再发散**；踢击期间实际增益
  全程为 −1.0（由 `dx_error / kf_dx` 反推确认），说明门控按设计让位。
- 遗留问题：硬踢之后系统会停在一个**更大的极限环**（55–103 mm），回不到
  22 mm。这是静摩擦的非线性滞回，改增益解决不了，需要摩擦前馈或独立的
  恢复期机制。两次恢复过程中轮电流顶到 15000 饱和，说明恢复本身已接近
  硬件极限。

运行时参数：`dx_feedback_gain_static`、`dx_static_delay_ms`、
`dx_static_speed_limit`。
